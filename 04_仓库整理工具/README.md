## Move-WebDemo.ps1

**性质**：为 **2026-10 仓库结构重组**编写的一次性脚本。
保留在此仅为**记录归档过程**，便于日后追溯"当时的目录是怎么移动的"。

### 为什么保留而不是删除

| 理由 | 说明 |
|---|---|
| **可追溯** | 重组涉及 80 个文件的重命名，脚本记录了权威的源/目标路径 |
| **可复用** | 若将来还需要做同类"整体移动目录"的操作，它的检查逻辑可直接借鉴 |
| **可审计** | 脚本本身证明了移动是**原子且可预览**的，没有覆盖或丢失文件 |

### 安全设计（为什么它不是危险脚本）

原作者把它写成"预览优先"，这是正确的做法：

| 保护 | 行为 |
|---|---|
| **默认只预览** | 不加 `-Apply` 时只打印计划，不移动任何文件 |
| **拒绝猜测** | 找不到 `trainee-deity` 时**直接报错退出**，不去猜别的目录 |
| **拒绝覆盖** | 目标 `01_WebDemo` 已存在时**报错停止**，绝不覆盖 |
| **检查工作区** | `-Apply` 前先跑 `git status --porcelain`，有未提交改动就拒绝执行 |
| **原子移动** | 用 `git mv`，保留文件历史（实测 80 个文件被识别为 `R100`/`R092`） |

### 现在运行会发生什么

```
Error: 未找到 trainee-deity 目录。脚本不会猜测其他目录。
```

因为 `trainee-deity/` 已被移动为 `01_WebDemo/`，脚本会**安全地失败**，不会造成任何破坏。
即使源目录被人为重建，它也会因目标已存在而再次拒绝执行。

### 用法（仅供理解，请勿执行）

```powershell
# 预览（安全）
.\Move-WebDemo.ps1 -RepoPath <仓库根>

# 执行（需先提交干净工作区）
.\Move-WebDemo.ps1 -RepoPath <仓库根> -Apply
```

> **执行策略提示**：Windows 默认禁止运行未签名脚本，需用
> `powershell.exe -NoProfile -ExecutionPolicy Bypass -File Move-WebDemo.ps1`
> （本次执行即采用此方式，**未修改系统级执行策略**）。

## 实际执行记录

完整记录见 [`../03_设计文档/WebDemo归档说明.md`](../03_设计文档/WebDemo归档说明.md) 的「执行记录」节，要点：

| 情况 | 处理 |
|---|---|
| `git mv trainee-deity 01_WebDemo` 反复报 `Permission denied`（ACL 与对照目录完全一致） | 定位为 **`trainee-deity/docs/` 子目录阻塞父目录重命名**；改为「先移走 `docs/` 内容 → 删空目录 → 再重命名父目录」 |
| 移动后浏览器测试报"依赖未安装" | pnpm 的 `playwright-core` 是 **Junction（绝对路径 target）**，重命名后悬空；删 `node_modules` 用 pnpm 重装即修复 |
| `docs/` 下混有技术文档（与"原型 / 剧情 / 设计"分离原则冲突） | 技术文档移出到 `03_设计文档/Web原型/`，使 `01_WebDemo/` 成为纯可运行原型 |
| CI 工作流在 `trainee-deity/.github/`（GitHub 只读仓库根的 `.github/`） | **提到仓库根**——该 CI 此前从未被加载过 |
