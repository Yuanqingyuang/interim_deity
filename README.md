从两百人的**蛮荒**聚落，到六万人的**星际**文明——**五个时代，一座岛**。

| 项 | 值 |
|---|---|
| 类型 | 城市建造 + 神明养成（**无战斗**） |
| 当前可玩形态 | **Web Demo**（纯静态网页，浏览器打开即玩） |

## 三、快速开始

### 运行 Web Demo

```bash
cd 01_WebDemo
python3 -m http.server 8080     # 或 npx serve .
# 浏览器打开 http://127.0.0.1:8080/
```

> ⚠️ ES Module **不能**用 `file://` 打开，必须经 HTTP。
> 调试用 `?debug=1`（FPS/DrawCall 面板），`?seed=20260921` 指定世界种子。

### 跑测试

```bash
cd 01_WebDemo
npm run verify                  # lint + 17 个单测（零依赖，必过）
npm run test:browser            # 7 个浏览器回归（需静态服务）
```

### 打包部署

```bash
node <本机工具>/package.mjs      # 产出 dist/trainee-deity-v1.1.0.{zip,tar.gz,sha256}
```

部署要点：**必须启用 HTTPS**（否则密码 KDF 会降级为弱哈希）；
必须设 `Cache-Control: no-cache`（本项目无构建哈希，长缓存会导致改版后老用户跑旧代码）。
详见 `03_设计文档/Web原型/project-docs/13_构建部署与发布.md`。

## 五、仓库重组记录（2026-10）

本次重组的三个决定：

1. **不逐行翻译 JavaScript** —— Unity 版应把模拟数据与 GameObject 分离
   （Web 版 `main.js` 承担了主循环、暂停、自动建造、存档接线等多项职责，Unity 版必须拆开）
2. **数值规则以当前 Demo 为基准** —— 从实际配置导出参数、用相同输入对照两版结果，
   **不要**在 Unity 中重新估算一套"看起来相近"的公式
3. **剧情、评分、原型分开管理** —— 见 §二 的三类内容表

### 重组中修复的一个真实缺陷

CI 工作流原先位于 `01_WebDemo/.github/`（重组前为 `trainee-deity/.github/`），
而 **GitHub Actions 只读取仓库根的 `.github/workflows/`** → **该 CI 从未被加载过**。
现已移至仓库根并加 `working-directory: 01_WebDemo`。

### 未改动的内容（重要）

以下名称**故意保持 `trainee-deity` 不变**，因为它们是标识符而非路径，改动会造成破坏：

| 项 | 值 | 改动后果 |
|---|---|---|
| 存档键名 | `trainee-deity-save-v3` | **老玩家存档全部失效** |
| 存档导出文件名前缀 | `trainee-deity-<slot>-<ts>.json` | 玩家备份文件无法被识别 |
| 打包产物名 | `trainee-deity-v1.1.0.{zip,tar.gz}` | 既有部署脚本失效 |
| `package.json` 的 `name` | `trainee-deity` | npm 包标识 |

## 六、已知限制（面向玩家）

- **存档在浏览器本地**：换设备、换浏览器、清理浏览器数据都会丢失进度。
  请用存档对话框的「导出 JSON」定期备份。
- **无云存档、无账号服务器**：纯本地单机（实测代码内零网络请求）。
- **无遥测**：开发者看不到线上玩家的流失点，也不知道真实设备的性能表现。
- **性能数据来自软件渲染**：开发环境用 SwiftShader（无 GPU），帧率偏低；
  真实显卡/手机上的表现**尚未验证**。
- **无失败条件**：不会输，只会变慢。详见 `18_游戏结束条件与终局判定.md`。
