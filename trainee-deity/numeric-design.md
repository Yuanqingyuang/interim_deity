# 实习神明 · 数值体系设计（公式规范）

> 本文档定义《实习神明》全部需要公式约束的数值：常量、时代参数、建筑上下限、资源产出、人口上限、产能与建造速度。
> 曲线采用**方案 B（前慢后快）**，时代取值为 **E = 1…5**。

> **实现口径（2026-09-15 复查）**：奇迹消耗为 **信仰**（`WONDERS.faithCost`），非产能公式；
> `faithCost` 现由 `FAITH_ERA_BASE[E] × FAITH_FILL_SEC` **推导**，不再手填（见 §4 ④）。
> 星星改为 **每时代 3 个里程碑**（见 `js/config.js` MILESTONES），不再随 faithRate 时间累积；
> 进阶条件 = 人口达标 +（E2 起）本时代奇迹 + 星星 ≥ starCost + 产能/秒 ≥ GATE(E)=0.5×刚需工业产能；
> 粮/产/信仰与住房均按 **已建成 built** 产出。建筑代理比与完整 §8 打分场仍未实现。

> 本文件与 `js/config.js` 配合使用；参数变更请以本表为准并同步回代码。

## 〇、已锁定的设计决策

| 项 | 决策 |

| 增长曲线 | 方案 B 前慢后快：200 → 2,000 → 5万 → 500万 → 50亿 |
| 建筑种类 | 四类核心：房子 / 农田 / 工业区 / 教堂 |

## 三、公式集

### ① 时代
```
M(E) = T(E) / T(1)
```

### ② 人口（三重约束 + 分阶段主导）
```
N_high(E) = T(E)
N_low(E)  = T(E-1)            // E=1 时为 20

N_cap(E) =
    E ≤ 2   :  房子数 × C_HOUSE                    // 住房主导
    3 ≤ E ≤ 4 : ⌊ 农田数 × C_FARM / R_FOOD ⌋       // 粮食主导
    E = 5   :   ⌊ 工业数 × K_IND / R_INDPOP ⌋      // 产能主导

人口增长：
    N ← min( N_cap , N × (1 + g(E)·dt) + 0.6·dt )
    约束：粮食/秒 ≥ N × R_FOOD
```

### ③ 建筑上下限（四类通用）
```
人均系数 r_b：房子 0.25 | 农田 0.20 | 工业 0.15 | 教堂 0.05

建筑_low(E)  = ⌈ T(E) × r_b ⌉            // 刚需：不卡关
建筑_high(E) = ⌈ T(E) × r_b × K ⌉        // 时代容量：防溢出（K = 1.25）
```

### ④ 资源产出
```
粮食/秒   = 农田数 × C_FARM
粮食消耗/秒 = N × R_FOOD
信仰/秒   = (教堂数 × K_CHURCH + N × K_FAITH_POP) × D(E)     // D(E) 见下方「信仰的时代阻尼」
产能/秒   = 工业数 × K_IND
```

#### 信仰的时代阻尼 D(E)（2026-09-15 修订）

原始公式两项都**线性于人口**，而人口每时代涨 10~1000 倍、奇迹消耗只涨约 10 倍，
结果是后期信仰「秒出」（E5 仅需 0.001s 就能攒满太空电梯），信仰经济失效。

改为按时代给出**基准产出**，人口与教堂只决定时代内的相对进度：

```
D(E)      = FAITH_ERA_BASE[E] ÷ (0.2 × T(E))     // 0.2 = 刚需教堂数下 原始产出 / 人口
D         = [0.375, 0.375, 0.15, 0.015, 0.00015]
信仰/秒    = FAITH_ERA_BASE[E]                   // 满规模（人口达标 + 刚需教堂）
奇迹消耗    = FAITH_ERA_BASE[E] × FAITH_FILL_SEC  // 由产出推导，不再手填
```

**关键不变量**：每个时代「满规模攒满本时代奇迹」耗时一致 = `FAITH_FILL_SEC`（100s）。
这条不变量已写成回归断言（`test/r11-p3.test.mjs`），改动参数时会立刻报警。

### ⑤ 建造速度（建造快慢 = 需求 × 产能）
```
单位产能需求：c_build(E) = C0 × e(E)，   e(E) = 1.5^(E-1)
产能需求/秒  = 待建建筑数 × c_build(E)
建造速度：    V(E) = V0 × clamp( 产能/秒 ÷ 产能需求/秒 , 0.2 , 2.0 )
```

### ⑥ 产能（第四资源）三大出口
```
a) 建造 / 升级建筑：持续扣产能（由 ⑤ 的 V 驱动）
b) 世界奇迹：一次性 coinCost(E) = 建造时长(E) × 产能/秒
c) 时代进阶门槛：产能/秒 ≥ GATE(E)
```

## 五、关键校验（设计约束）

### 🔴 约束 1：产能主导阶段必须可达标
```
R_INDPOP ≤ R_IND × K_IND = 0.15
```
- 取 `R_INDPOP = 0.12` → E5 人口上限 **62.5 亿 ≥ 50 亿 ✓**
- 取 `R_INDPOP = 0.25` → E5 人口上限仅 **30 亿 ✗ 卡死**

### 🟢 结论 2：low / high 的意义被验证
三重约束在 **low 配置下系数恰好 = 1.00**（供需刚好持平）；乘 `K = 1.25` 后才产生 25% 富余。
→ `low` 保证不卡关，`high` 提供缓冲，两者不可合并。

### 🟡 结论 3：后期产能需求增长曲线
建造速度随时代单调下滑（0.084 → 0.017），维持满速所需工业配比从 **0.125 升到 0.633**。
→ 后期玩家必须大幅加建 / 升级工业区，形成「产能追赶」的长线目标。

## 七、村民渲染数量（视觉代理·方案甲）

> 逻辑人口 `N` 在星际时代达 **50 亿**，与屏幕可渲染人数必须**解耦**。
> 本节只定义数值映射；渲染实现方式（InstancedMesh / 分布 / LOD）暂不纳入范围。

### 7.1 映射公式（对数压缩）

```
N_render = clamp( round( 50·log10(N) − 85 ) , min(E) , max(E) )

显示比例 p(E) = N_render / N          // 逐时代递减（见 7.2）
代理比        = 1 / p(E) = N / N_render   // 1 个渲染村民代表的实际村民数
```

### 7.2 每时代渲染上下限 与 显示比例

| E | 时代 | min(E) | max(E) | 目标渲染 R(E) | **显示比例 p(E)** | 代理比 q(E)=1/p |
|---|---|---|---|---|---|---|
| 1 | I 蛮荒 | 10 | 60 | 30 | **0.15** | 6.7 |
| 2 | II 城邦 | 50 | 120 | 80 | **0.04** | 25 |
| 3 | III 封建 | 100 | 200 | 150 | **0.003** | 333 |
| 4 | IV 工业 | 165 | 300 | 250 | **5×10⁻⁵** | 20,000 |
| 5 | V 星际 | 250 | 400 | 400 | **8×10⁻⁸** | 12,500,000 |

> **显示比例 `p(E)` 逐时代递减** —— 时代越高，同样人口下显示的人越少（即 1 : q(E)）。
> 上限 **400** 为移动端红线；下限保证部落 / 城镇有基本人气。
> ⚠️ 实测：对数公式下时代进阶会有**小幅跳升**（E1→E2 **+20**、E2→E3 **+20**、E3→E4 **+15**、E4→E5 **0**）。
> 若要求**完全无缝**，改用线性方案：`N_render = clamp( N ÷ q(E), min(E), max(E) )`。

### 7.3 各时代目标人口下的渲染结果

| E | 时代 | T(E) 目标人口 | N_render | 代理比（1 人代表） |
|---|---|---|---|---|
| 1 | I 蛮荒 | 200 | 30 | 7 |
| 2 | II 城邦 | 2,000 | 80 | 25 |
| 3 | III 封建 | 50,000 | 150 | 333 |
| 4 | IV 工业 | 5,000,000 | 250 | 20,000 |
| 5 | V 星际 | 5,000,000,000 | 400 | 12,500,000 |

### 7.4 现状问题与说明

- **现状**（`js/main.js`）：`n = min(40, √pop × 1.2)`。星际时代 `√5e9 × 1.2 ≈ 84,852`，被硬夹到 **40**，导致**从城邦时代起视觉完全停滞**，玩家看不到文明长大。
- 本方案以「对数压缩 + 每时代上下限」替代该公式，兼顾**视觉成长感**与**移动端性能**。
- 时代配色沿用已有的 `FOLKCOL[E]` 与 `FOLK_HEAD`（换时代自动换装）。

## 八、建筑自动生成位置推算（方案乙 · 打分场）

> **机制前提**：玩家**只划「居住区」**作为锚点；农田 / 工业 / 教堂由系统在满足约束的空位**自动落位**。
> 建筑占 1 格，不可落在水面或已占用格。

### 8.1 输入 / 输出

```
输入：居住区格集合 R、各类型目标数量 n_t、已建建筑集合 B、地形（水面 / 高度）
输出：本批次建筑的坐标列表 [(x, y), ...]
```

### 8.2 基础量

**到居住区距离**（切比雪夫距离，0 = 在居住区内）
```
D_res(c) = max( |cx − nearest(R).x| , |cy − nearest(R).y| )
```

**间隔**
```
gap(c, c') = max(|cx−c'x|, |cy−c'y|) − 1      // ≥0 表示至少相邻
规则：gap(农田, 农田) ≥ 0 ；其余任意组合 gap ≥ 1
```

**方形度**（衡量加入 c 后簇有多"正方"）
```
S(c) = n' / (w'·h')  ×  (1 − |w'−h'| / max(w',h'))
     = 填充率        ×   方正度          // 完美实心正方形 = 1
其中 w',h' = 加入 c 后簇包围盒的宽 / 高，n' = 加入后格子数
```

**区块（Chunk）** —— 渲染以 10×10 区块为单位
```
区块尺寸   S_chunk = 10
区块坐标   C(c) = ( ⌊cx / 10⌋ , ⌊cy / 10⌋ )
区块距离   D_chunk(C₁, C₂) = max( |ΔCx| , |ΔCy| )      // 以区块为单位
区块负载   occupancy(C) = 区块内建筑数 ÷ BlockCap      // 硬约束：occupancy < 1
区块容量   BlockCap = 25 座/区块
```
> 地图 34×34 → 区块 4×4 = **16 个区块**；同区块内最大切比雪夫距离 = **9 格**。

### 8.3 打分函数

```
score(c) = w₁·S(c) + w₂·A_same(c) + w₃·A_other(c) + w₄·A_anchor(c) + w₅·A_chunk(c) − P(c)

A_same(c)   = 1 / (1 + d_same)                  // 同类吸引：越近越高
A_other(c)  = min(1, d_other / D_max)           // 异类排斥：越远越高
A_anchor(c) = 按类型取值（见 8.4）
A_chunk(c)  = 2.0·typeShare(C(c), t) − 1.0·occupancy(C(c))    // 区块亲和
              typeShare = 区块内 t 类建筑数 ÷ 区块内建筑总数（空区块取 0.5 中性）
P(c) = 10·[间隔违规] + 10·[D_res 越界] + 10·[区块满载] + 4·( max(0, (d_other − D_max) / D_max) )²

权重：w₁ = 3.0（方正）  w₂ = 2.0（同类聚集）  w₃ = 1.5（异类分离）  w₄ = 2.5（锚点）  w₅ = 2.0（区块）
```

### 8.4 类型约束表

| 类型 | 批次大小 | D_res 合法域 | A_anchor | 与同类间隔 | 与其他间隔 |
|---|---|---|---|---|---|
| 教堂 | 1 | `[0, 0]`（居住区内） | `−D_res` | ≥1 | ≥1 |
| 房子 | 按缺口 | `[0, 0]`（居住区内） | `−D_res` | ≥1 | ≥1 |
| 农田 | 按缺口 | `[1, R_farm]`（紧邻带） | `1 − |D_res − 1| / R_farm` | **0** | ≥1 |
| 工业 | 2 | `[R_ind, ∞)`（远离） | `min(1, (D_res − R_ind) / R_ind)` | ≥1 | ≥1 |

> `D_res` 越界即在 `P(c)` 中重罚（10 分），因此每个类型只会在自己的合法环带内落位；
> `A_other` 抬高异类距离、`P_far` 惩罚超过 `D_max` 的情况 → 同时满足「独立」与「不相隔太远」。

### 8.5 批次生成流程

```
按优先级（由内到外）：教堂 → 房子 → 农田 → 工业
区块归属与"溢出到下一区块"的判定见 8.8。

for t in 优先级顺序:
    n = 本类型待建数_t
    while n > 0:
        k = min(n, batch_t)                 // 教堂 1，工业 2，其余 ≤ 9
        s = ⌈√k⌉                            // 方阵边长 → 规则①（正方，不是 T 字）
        offsets = { (i mod s, ⌊i/s⌋) : i = 0..k−1 }
        若 k < s²：从 4 个角开始剔除，保证剩余仍是方阵
        best = argmax over 候选左上角 c₀ 的 Σ score(c₀ + offset_i)
        落位 best；n -= k
```

**批次方阵示例**
```
k = 1 → 1×1      k = 2 → 1×2      k = 4 → 2×2
k = 5 → 3×3 去 4 角      k = 9 → 3×3
```

### 8.6 参数表（34×34 网格）

| 参数 | 含义 | 建议值 |
|---|---|---|
| `R_farm` | 农田外边界（紧邻居住区） | 3 |
| `R_ind` | 工业最小距离（远离居住区） | 6 |
| `D_max` | 异类簇最大中心距（不许太远） | **8**（≤ 同区块内，同块最大 9 格） |
| `S_chunk` | 区块尺寸（34×34 → 4×4 = 16 区块） | 10 |
| `BlockCap` | 单区块建筑容量上限 | 25 座 |
| `D_chunk_max` | 跨区块最大区块距离 | 1（仅相邻区块） |
| `gap_min` | 非农田建筑间隔 | 1 |
| `gap_farm` | 农田间隔 | 0 |
| batch | 教堂 / 工业 / 房子 / 农田 批次 | 1 / 2 / ≤9 / ≤9 |
| `s_max` | 单簇方形边长上限 | 5 |
| `w₁`–`w₅` | 打分权重 | 3.0 / 2.0 / 1.5 / 2.5 / 2.0 |

### 8.7 调参指引

- 想让布局更"方正"：↑ `w₁`（过大时建筑会挤成方块而忽视距离，需配合 ↑ `w₄`）。
- 想更严格分区：↑ `w₃` 与 `P(c)` 中的间隔/越界罚分。
- 想让四类更靠近：↓ `D_max`。
- 农田带太窄 / 太宽：调 `R_farm`；工业太贴城：↑ `R_ind`。

### 8.8 区块填充规则（fill-first + 溢出 · 四类通用）

**规则**：优先把同一类型填满它所在的区块；但若该区块内剩余地块**给其他类型打分更高**，则该建筑**溢出到下一个区块**。

```
对类型 t 的下一座建筑：
  C* = 候选区块
       = t 的簇所在区块；若 t 尚无建筑，取距居住区最近的合法区块

  在 C* 的合法空格上分别求两类最优分：
      s_t     = max  score_t(c)                      // 放 t 的最高分
      s_other = max  max_{t' ≠ t} score_{t'}(c)      // 放其他类型的最高分

  if s_t ≥ s_other:
      → 落位 argmax score_t(c)      // 本区块被 t 认领，继续填同类
  else:
      → 本区块留给其他类型，t 溢出到下一区块
        下一区块按 D_chunk 升序取（相邻优先），且 D_chunk ≤ D_chunk_max = 1
```

**区块类型归属**：一个区块的"归属类型" = 该区块内数量最多的建筑类型；后续同类型建筑优先回填该区块。

**各类型的候选区块与溢出范围**（溢出后仍必须落在该类型自己的合法域内）

| 类型 | 候选区块 C* | 溢出范围 | 溢出/落位后仍须满足 |
|---|---|---|---|
| 教堂 | 含居住区的区块 | 其他含居住区的相邻区块 | `D_res = 0`、`occupancy < BlockCap`、间隔 ≥1 |
| 房子 | 含居住区的区块 | 其他含居住区的相邻区块 | `D_res = 0`、`occupancy < BlockCap`、间隔 ≥1 |
| 农田 | 紧邻带（`D_res` 1–3）所在区块 | 紧邻带内的相邻区块 | `1 ≤ D_res ≤ R_farm`、间隔：同类 **0** / 异类 ≥1 |
| 工业 | 满足 `D_res ≥ R_ind` 的区块 | 满足 `D_res ≥ 6` 的相邻区块 | `D_res ≥ R_ind`、`occupancy < BlockCap`、间隔 ≥1 |

> **教堂 / 房子的特殊情况**：它们的合法域是 `D_res = 0`，只能落在居住区格子上；因此其"溢出"不是离开居住区，而是**在居住区横跨多个区块时，从当前居住区区块换到相邻的另一个居住区区块**。

**四类统一流程**
```
for t in [教堂, 房子, 农田, 工业]:            // 由内到外
    while 本类型待建数 > 0:
        C* = t 的簇所在区块（若 t 尚无建筑 → 合法域内距居住区最近的区块）
        s_t     = max  score_t(c)                over 合法空格 c ∈ C*
        s_other = max  max_{t' ≠ t} score_{t'}(c)

        if s_t ≥ s_other:  落位本区块（argmax score_t）
        else:              t 让出本区块，溢出到 D_chunk ≤ 1 的相邻区块

        落位前硬校验：该类型 D_res 合法域 ∧ occupancy < BlockCap ∧ 间隔规则
```

**示例**
```
· 工业簇所在区块剩余地块对农田打分更高 → 工业让出，落到相邻区块
· 农田簇所在区块剩余地块对房子/教堂打分更高 → 农田溢出到相邻的紧邻带区块
· 房子：居住区横跨 A/B 两区块时，A 块填满后溢出到 B 块（仍满足 D_res = 0）
```

**容量提示（待处理）**：区块物理容量 ≈ 16 × 25 = **400 座可见建筑**，而逻辑建筑数在 E4 / E5 达百万～亿级 → 建筑需要与村民一致的「代理比」，否则数值与可渲染规模对不上。
