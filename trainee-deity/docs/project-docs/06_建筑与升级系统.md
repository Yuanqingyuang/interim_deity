## 〇、先澄清：本项目**没有建筑等级制**

| 常见"建筑升级"要素 | 本项目状态 |
|---|---|
| 建筑等级（Lv1→Lv10） | 【不适用】无。每栋建筑只有"建造中 / 已建成"两态 |
| 升级消耗资源 | 【不适用】无 |
| 升级时间 | 【不适用】无 |
| 建筑技能 / 效果解锁 | 【不适用】无 |
| 建筑星级 / 品质 | 【不适用】无 |
| 建筑单独属性面板 | 【不适用】无 |

**本项目实际有的是**：

| 真实机制 | 说明 |
|---|---|
| **四类分区** | 居住 / 农田 / 工业 / 信仰，各自单一职能 |
| **建造进度 `prog`（0→1）** | 唯一的"成长"过程；进度期间建筑做缩放动画 |
| **时代形体分化** | 同一类建筑在五个时代有**完全不同的形体**（4 × 5 = 20 套） |
| **外观变体 `variant`** | 每类建筑有 0–2 三种微变体（由确定性哈希决定） |
| **时代上下限 low/high** | 决定"该建多少"，而非"建得多强" |
| **多体聚落副楼** | `BUILD_Q > 1` 时每格补 2–3 个缩小的副楼 |

> **"成长"的载体是时代，不是单栋建筑。** 时代进阶后，**已建成的建筑外观也会随之改变**
> （因为形体由当前时代决定），玩家会看到整座城市"换了一个时代的样子"。

## 一、四类建筑

【已实现】`config.js:41 MILESTONES` 的 `ctx` 与 `formulas.js:27 NUM.R_B` 定义人均系数

| zone | 名称 | 人均系数 $r_b$ | 单栋核心产出 | 主要作用 |
|---|---|---|---|---|
| 1 | **居住（房屋）** | 0.25 | 容纳 `C_HOUSE = 4` 人 | E1–2 人口上限；住房压力 |
| 2 | **农田** | 0.20 | 产 `C_FARM = 50` 粮/秒 | E3–4 人口上限；养活人口 |
| 3 | **工业** | 0.15 | 产 `K_IND = 1.0` 产能/秒 | 建造速度；E5 人口上限；进阶门槛；奇迹施工 |
| 4 | **信仰（教堂）** | 0.05 | 产 `K_CHURCH = 2` 信仰/秒 | 信仰经济 |

### 1.1 刚需（low）与时代容量（high）

$$buildingLow(E, z) = \left\lceil T(E) \cdot r_b(z) \right\rceil \tag{17}$$

$$buildingHigh(E, z) = \left\lceil T(E) \cdot r_b(z) \cdot K \right\rceil, \qquad K = 1.25 \tag{18}$$

**出处**：`numeric-design.md §3③` ｜ 实现 `js/formulas.js:68-73`

### 1.2 完整核算表（逻辑口径）

| E | $T(E)$ | 居住 low/high | 农田 low/high | 工业 low/high | 信仰 low/high |
|---|---|---|---|---|---|
| 1 | 200 | 50 / 63 | 40 / 50 | 30 / 38 | 10 / 13 |
| 2 | 2,000 | 500 / 625 | 400 / 500 | 300 / 375 | 100 / 125 |
| 3 | 8,000 | 2,000 / 2,500 | 1,600 / 2,000 | 1,200 / 1,500 | 400 / 500 |
| 4 | 20,000 | 5,000 / 6,250 | 4,000 / 5,000 | 3,000 / 3,750 | 1,000 / 1,250 |
| 5 | 60,000 | 15,000 / 18,750 | 12,000 / 15,000 | 9,000 / 11,250 | 3,000 / 3,750 |

**low / high 的设计意义**【出处：`numeric-design.md §五 结论 2】：

- **low = 刚需** —— 达到即"不卡关"（人口目标可达）
- **high = 时代容量** —— 上限的 1.25 倍，防溢出

【已实现·已修复】**关键**：`autoBuild` 的 `need[]` 必须在此区间内，且**达标后归零**：

$$need_z = \begin{cases} low_z & cnt_z < low_z \\ \min(high_z,\ cnt_z) & cnt_z \ge low_z \end{cases} \tag{19}$$

> ⚠️ 若写成 $cnt_z + k$，$need$ 会**恒大于** $cnt$ → 缺口判定恒真
> → **无条件刷到 high 水位（把岛铺满）**。这是历史上的 **S-04 棘轮**，
> 详见 `01_游戏概述与核心循环.md §2.5`。回归测试：`test/rev-6-autobuild.test.mjs`。

### 1.3 地块口径（放置目标）

因地图有硬上限（≈1,350 格），放置目标必须用**地块口径**：

$$buildingLowTiles(E,z) = \left\lceil \frac{buildingLow(E,z)}{q_b(E)} \right\rceil \tag{20}$$

$$q_b(E) = \text{BUILD\_Q}[E] = [1,\ 1,\ 3,\ 6,\ 20]$$

**完整地块口径表**

| E | $q_b$ | 居住 low | 农田 low | 工业 low | 信仰 low | 关键路径合计 |
|---|---|---|---|---|---|---|
| 1 | 1 | 50 | 40 | 30 | 10 | **69** |
| 2 | 1 | 500 | 400 | 300 | 100 | **698** |
| 3 | 3 | 667 | 534 | 400 | 134 | **921** |
| 4 | 6 | 834 | 667 | 500 | 167 | **1,185** |
| 5 | 20 | 750 | 600 | 450 | 150 | **1,060** |

> ⚠️ **两个口径绝不可混用**。传错会让后期产出少算 $q_b$ 倍（**E5 差 20 倍**）。
> 历史上踩过两次：`housingCap` 漏乘 `BUILD_Q`（导致无脑建房）、
> `buildSpeed` 收到地块数（导致 E5 内部供给只有 HUD 的 1/20）。
> 详见 `09_数值与公式手册.md §9`。

## 二、五时代建筑形体（20 套）

【已实现】`config.js BUILDING_STYLE` + `render.js` 的 20 个构建器

### 2.1 设计原则

【出处】`E:\sxsm\时代建筑外观规划.md`

> 真正的缺口：**只有配色，没有形体**

原实现只有 `wall/side/roof` 三色随时代变化，**形体完全一致** ——
玩家进阶后看到的是"同一栋房子刷了层新漆"，缺乏文明跃迁的观感。
2026-10 重构为**按时代分派到不同几何构建函数**。

### 2.2 住房五型（`_house*`）

| E | 时代 | 形体 | 构建器 | 参数（`h` 高度） | 特色 |
|---|---|---|---|---|---|
| 1 | 蛮荒 | **圆筒 + 锥顶草棚** | `_houseRound` | 0.9 | `body:'cyl'`、`roof:'cone'`、`deco:'thatch'` |
| 2 | 城邦 | **方屋 + 人字顶 + 柱廊** | `_houseBox` | 1.2 | `extras:['columns']` |
| 3 | 封建 | **方屋 + 陡尖顶 + 扶壁** | `_houseBox` | 1.4 | `extras:['buttress']`、`glow` 发光窗 |
| 4 | 工业 | **排屋（长条多层）** | `_houseLonghouse` | 由 `form` 决定 | 密集排布，工业时代感 |
| 5 | 星际 | **多层几何体 + 发光** | `_houseCommon` + 高 `BUILD_Q` 副楼 | 最高 | `glow` 发光 |

**多体聚落**：$q_b(E) > 1$ 时（E3 起），`render.js:_houseCluster` 为每格补 **2–3 个缩小的副楼**，
使"1 格 = N 栋"在画面上可信。
副楼**复用主楼的几何/材质缓存**，故**不新增合批槽位**。

### 2.6 外观变体 `variant`

【已实现】每格 `variant = (hash2(x, y, seed+13) × 3) | 0`，取值 **0 / 1 / 2**。

**作用**：同一时代同一类建筑在地图上呈现三种微差异（如屋顶朝向、装饰有无），
避免整片区域完全重复。

**确定性**：由 `hash2` 决定 → **同种子同外观**，可复现。

## 三、建造机制

### 3.1 两态与进度

```
zone 已划定 (prog=0, built=false)
        │  每 tick: prog += V(E)·dt·(1 + boostBuild 加速)
        ↓
prog ≥ 1  →  built = true
        │
        ↓
移入 InstancedMesh 批次（不再逐栋渲染）
```

**建造中的表现**：建筑按 `prog` 做**缩放动画**（从 0.25 缩放到 1.0），
并有半透明感 —— 让玩家直观看到"正在长起来"。

> **这解释了渲染层的双轨设计**：建造中建筑必须走独立 `Group`（每栋缩放值不同），
> 无法合批；完工后才能进入 `InstancedMesh` 批次。

### 3.2 建造速度

$$V(E) = V_0 \cdot \text{clamp}\!\left(\frac{\dot{I}_{out} - \dot{I}_{draw}}{\max(\epsilon,\ W_{pending} C_0 1.5^E)},\ \phi,\ 2.0\right)$$

（公式 (15)，完整解释见 `04_资源经济与生产链.md §6`）

**关键数值**：

| 参数 | 值 | 位置 |
|---|---|---|
| $V_0$ 基础速度 | 0.07 进度/秒 | `NUM.V0` |
| 上限倍率 | 2.0 | 内联 |
| 下限 $\phi$（有工业） | 0.2 | 内联 |
| 下限 $\phi$（无工业） | 0.5 | 内联 |
| 加速神迹倍率 | ×3 | `main.js:613` |

**单栋耗时速查**

| 情形 | $V$ | 游戏秒/栋 |
|---|---|---|
| 无待建 | 0.07 | ≈ 14.3 |
| 供给比 = 1 | 0.07 | ≈ 14.3 |
| 供给比 ≥ 2 | 0.14 | ≈ 7.1 |
| 严重不足（有工业） | 0.014 | ≈ 71.4 |
| **零工业开局** | 0.035 | ≈ **14.3**（特例保护） |
| 加速建造神迹中 | ×3 | ≈ 4.8 |

> **零工业特例**：E1 开局没有任何工业，若沿用 0.2 下限则首栋住房要 71 游戏秒，
> 玩家长时间看不到建筑落成。故无工业时改用村民"自建"底速 $0.5 V_0$。

### 3.3 建造消耗

【已实现】产能需求按 `BUILD_COST` 加权（式 8）：

| 分区 | 权重 $c_z$ | 含义 |
|---|---|---|
| 居住 | 0.6 | 最便宜 |
| 农田 | 0.8 | |
| 工业 | 1.6 | |
| 信仰 | 2.0 | 最贵 |

**归一性**：$0.25 \times 0.6 + 0.20 \times 0.8 + 0.15 \times 1.6 + 0.05 \times 2.0 = 0.65 = \sum r_b$ ✔
→ **不改变整体建造速度曲线**，只重新分配四类建筑的经济压力。

## 五、建筑的经济角色（为何四类缺一不可）

```
             ┌──────── 居住 ────────┐
             │ 唯一作用：提供住房   │
             │ 决定 E1–2 人口上限   │
             └──────────┬───────────┘
                        │ 人口
                        ↓
   ┌────────────────────────────────────────────┐
   │  人口是四类建筑的共同枢纽：                 │
   │  · 消耗粮食（R_FOOD = 1/人/秒）            │
   │  · 决定四类建筑的 low/high（T(E)）         │
   │  · 产生信仰（K_FAITH_POP = 0.1/人/秒）     │
   │  · 决定 E3–4 人口上限需多少农田            │
   └────────────────────────────────────────────┘
        ↑                ↑                ↑
   ┌────┴────┐    ┌──────┴──────┐   ┌────┴─────┐
   │  农田   │    │   工业      │   │  信仰    │
   │ 产粮    │    │ 产能→建造速度│   │ 产信仰   │
   │ E3–4上限│    │ E5上限/门槛 │   │ →奇迹    │
   └─────────┘    └─────────────┘   └──────────┘
```

**设计观察**：四类建筑的**刚需配比** $r_b$ 固定为 0.25/0.20/0.15/0.05（和为 0.65），
故它们的数量比恒为 **5 : 4 : 3 : 1**（居住最多、信仰最少）。
这给玩家一个稳定的城市形态预期。

## 六、自动建造（子民的建造决策）

【已实现】`js/autobuild.js`，详见 `03_城市建造与布局.md §4` 与 `01` 文档 §2.5

### 6.1 触发与限制

| 项 | 值 | 位置 |
|---|---|---|
| 间隔 | 每 **20 游戏秒** | `AUTO.interval` |
| 单轮上限 | **4** 次放置 | `AUTO.maxPerTick` |
| 工业单轮 | 最多 **2 格**（配对放置） | `AUTO.industryPerTick` |
| 住房压力阈值 | 人口/住房上限 > **0.85** | `AUTO.housingPressure` |
| 信仰压力阈值 | `faithRate` < **0.4** | `AUTO.faithPressure` |

### 6.2 六步优先级

【已实现】`autobuild.js buildOrder()`

| 序 | 行动 | 触发条件 |
|---|---|---|
| 1 | **住房** | `无住房` **或** `人口 ≥ 住房上限 − 0.5`（`forceHouse`） |
| 2 | 农田 | 农田缺口 |
| 3 | 工业 | 工业缺口（执行层另有 `pop ≥ 15` 门槛） |
| 4 | 住房（非紧急） | `粮产都有余` 且住房有缺口 |
| 5 | 教堂 | 教堂缺口 |
| 6 | 兜底住房 | 本轮 0 建成 且 住房仍缺 且（有农田 或 有粮产） |

**三条被测试锁定的不变量**：

- **A**：无住房时 `house` 必须置顶，且**不因资源门槛不足而被剔除**
- **B**：人口已达住房上限时 `house` 仍须置顶
- **C**：非紧急住房只在粮产都有余时才建

### 6.3 选址

【已实现】`terrain.js findAutoSite()` —— 打分场，详见 `03` 文档 §4

| 分区 | 选址方式 |
|---|---|
| 居住 / 农田 / 信仰 | 打分场（到居住质心距离 + 地形 + 聚集度） |
| **工业** | **专用** `placeIndustryBatch()`；禁止走 `findAutoSite(3)` |
