## 一、游戏定位

### 1.1 一句话

> 玩家扮演一名**见习神明**，用**神力**改造荒岛地形、划定四类区域，
> 子民**自动建造**并繁衍；人口与产能达标后可建造**世界奇迹**、**推进时代**，
> 历经**蛮荒 → 城邦 → 封建 → 工业 → 星际**五个时代，最终建成太空电梯通关。

### 1.2 类型与参照

| 项 | 内容 |
|---|---|
| 类型 | 城市建造（city-builder）+ 神明养成（god game） |
| 视角 | 3D 斜俯视，OrbitControls 相机（可旋转/平移/缩放） |
| 操作粒度 | **单格**（地块 1×1 世界单位），支持拖拽连续涂画 |
| 节奏 | 实时推进（`dt` 驱动），有暂停；无回合 |
| 核心张力 | **神力有限** —— 改造地形与划地都消耗神力，神力由信仰产出 |

> 【不适用】本项目**无战斗、无抽卡、无关卡、无匹配、无排行榜、无网络同步**。
> 判定依据与逐项说明见 `15_问题术语与TODO.md §2`。

## 二、四大核心循环

本项目**没有单一的"主循环"**，而是四个嵌套循环同时运转。理解它们是理解整个游戏的关键。

### 2.1 循环 A：局内操作循环（秒级）

```
玩家操作 → 消耗神力 → 地形/区域变化 → 产出变化 → 信仰增长 → 神力恢复
   ↑                                                              │
   └──────────────────────────────────────────────────────────────┘
```

| 环节 | 实现 | 代码 |
|---|---|---|
| 玩家操作 | 抬升/下沉/平整/引水/绿化 五工具 + 四类划区 + 拆除 | `config.js:97` `TOOLS` |
| 消耗神力 | 每工具 `cost`（划区 4、地形 5–8、拆除 1） | `terrain.js applyTool()` |
| 神力恢复 | `powerRegenOf(faithRate) = 2.5 + min(10, faithRate×0.02)` /秒 | `config.js:73` |
| 神力上限 | `powerMaxOf(era) = 100 + era×60` | `config.js:72` |

**关键设计**：神力**不是**随时间自然恢复的固定值，而是**由信仰产出驱动**
（`faithRate` 越高恢复越快，上限 +10/秒）。这形成"经济发展 → 神力更强 → 更能改造"的正反馈。

### 2.2 循环 B：子民自动建造循环（20 游戏秒级）

```
划定区域 → 子民按优先级自动建 → 建筑从「建造中」到「已建成」
   ↑                                        │
   └──── 产出增加 → 人口压力变化 ────────────┘
```

| 环节 | 实现 | 代码 |
|---|---|---|
| 触发 | 每 `AUTO.interval = 20` 游戏秒 | `config.js:76` |
| 决策 | 六步优先级（详见下） | `autobuild.js autoBuildDecision()` |
| 建造进度 | 每 tick 按 `buildSpeed` 推进 `prog` | `formulas.js:176` `buildSpeed()` |
| 完工 | `prog >= 1` → `built = true` | `main.js` tick |

**六步优先级**【已实现】（`autobuild.js buildOrder()`）：

1. **住房置顶**（若 `无住房` 或 `人口 ≥ 住房上限`）—— 破除死锁，见 §2.5
2. 农田缺口 → 建农田
3. 工业缺口 → 建工业
4. 非紧急住房（粮产都有余时才建）
5. 教堂缺口 → 建教堂
6. 兜底：本轮啥也没建成且住房仍缺 → 放宽门槛再补一次房

### 2.3 循环 C：成长与时代循环（分钟级）

```
人口/产能/星星 达标 ──→ 建造世界奇迹 ──→ 时代进阶 ──→ 解锁新时代外观与参数
   ↑                                                        │
   └──────────────── 新参数下继续发展 ←─────────────────────┘
```

**四项进阶条件**【已实现】（`progression.js eraReadiness()`）：

| 条件 | 说明 |
|---|---|
| ① 人口 `G.pop ≥ ERAS[era].popGoal` | 200 / 2,000 / 8,000 / 20,000 / 60,000 |
| ② 本时代奇迹已建成 | E1 无需奇迹；E2 起需 `G.wonders[era]` |
| ③ 星星 `G.stars ≥ starCost` | 恒为 3（每时代恰好 3 个里程碑，**零冗余**） |
| ④ 产能 `industryPerSec ≥ gateOf(era)` | `gateOf = 0.5 × 刚需工业产能` |

> ⚠️ **星星零冗余是硬锁风险**：3 个里程碑必须全部可得。历史上曾因里程碑指向
> 上一时代的奇迹导致**永久无法进阶**，详见 `08_时代进阶与里程碑.md §4`。

### 2.4 循环 D：世界扩张循环（长期）

```
城区变大 → 区块生成 → 地形网格重建（含旷野装饰）→ 可建造格增加
                     → 阴影正交框跟随城区中心与半径
```

| 环节 | 实现 | 代码 |
|---|---|---|
| 区块 | `CHUNK = 10`，开局 `4×4` 块居中 | `config.js:20-21` |
| 扩张触发 | 放置地块时 `ensureChunkRing()` | `terrain.js:223` |
| 地形重建节流 | 0.1s / 0.15s（`terrainDirty` 标记） | `main.js` tick |
| 阴影跟随 | `_syncShadow(cx, cz, half)`，半径钳制 `[20, 120]` | `render.js:508` |

> 【已实现】地形是**全世界一张网格**（非每区块一张），故**区块间不存在裂缝**。
> 顶点由全局 `ox/oy/W/H` 生成，区块只提供 `t.h`。

### 2.5 被刻意保护的三个"玩法灾难"

这三个是本项目历史上**真实发生过**的问题，现由测试锁定（`test/rev-6-autobuild.test.mjs`）：

| 灾难 | 成因 | 现状 |
|---|---|---|
| **住房死锁** | 房屋要求「8 邻域全空」，农田/工业会先占掉这类空格。若人口已被住房卡满时仍先放农田/工业，房屋再也找不到点位 → 人口永久停滞。极坏情形「一栋房都没有」：E1–2 人口上限 = 住房×`C_HOUSE` → `popCap=0` → 人口从 20 衰减到 1；而工业在 `pop<15` 时放弃 → 无工业 → `indOk` 恒假 → **永远建不出第一栋房**（当时实测人口卡在 1，农田却建到 40+ 格、粮产 45/s） | 【已修复】住房置顶且不因资源门槛被剔除 |
| **S-04 棘轮** | `need[z] = cnt[z] + 2` 使 `need` 恒 `>` `cnt` → 三个缺口判定恒真 → **无条件刷到 high 水位（把岛铺满）** | 【已修复】达标后 `need = min(hi, cnt)` |
| **信仰爆炸** | 信仰 = 教堂项 + 人口项，两项都线性于人口，而人口每时代涨 10~1000 倍、奇迹消耗只涨约 10 倍 → 后期信仰「秒出」（E5 仅需 0.001s 攒满太空电梯），**信仰经济失效**（旧版实测城邦时代囤到 2300 万，奇迹只需 1.5 万） | 【已修复】引入时代阻尼 `FAITH_ERA_DAMP` + `faithCapOf` 库存上限 |

## 三、完整玩法流程（从开局到通关）

```
[登录/注册]
     │  localStorage 本地账号（PBKDF2 或 FNV 降级）
     ↓
[新游戏] ── seed 生成世界 ── 出生地自带「5 房 + 1 农田」（已建成，住房上限=开局人口 20）
     │
     ↓
[E1 蛮荒时代]  人口目标 200 ── 无需奇迹
     │  操作：绿化/划居住 → 子民自动建 → 划农田保粮 → 划工业 → 划信仰
     │  3 里程碑：人口≥50 / 农田≥10 / 教堂≥1
     ↓  四项达标 → 点「时代进阶」
[E2 城邦时代]  人口目标 2,000 ── 需建「金字塔」（1500 信仰）
     │  3 里程碑：人口≥400 / 工业≥8 / 金字塔完成
     ↓
[E3 封建时代]  人口目标 8,000 ── 需建「大教堂」
     │  人口上限转折点：E1–2 住房主导 → E3–4 **粮食主导**
     ↓
[E4 工业时代]  人口目标 20,000 ── 需建「摩天塔」
     │  3 里程碑：人口≥1万 / 工业≥200 / 摩天塔完成
     ↓
[E5 星际时代]  人口目标 60,000 ── 需建「太空电梯」（1500 万信仰）
     │  人口上限转为**产能主导**；E5 是终点，不再进阶
     ↓
[通关] 建成太空电梯 → winScreen
```

## 五、玩法设计的三条核心决策

### 5.1 时代缩放只通过 `T(E)` 出现一次

【出处】`numeric-design.md:40`

> 村民数量 $N$ 为**绝对人口**。时代缩放**只通过 $T(E)$ 出现一次**；建筑数量 $\propto$ 人口，
> 因此单产系数**不再乘时代倍率**（避免二次放大，这是原始模板的主要缺陷）。

**含义**：单农田永远产 50 粮/秒，不随时代变化。时代的"更大"体现在
**需要更多建筑**，而不是"每栋建筑更强"。这让数值曲线可预测、便于平衡。

### 5.2 人口上限分阶段主导

$N_{cap}(E) = \begin{cases}
\text{房子数} \times C_{HOUSE} & E = 1,2 \\
\left\lfloor \text{农田数} \times C_{FARM} / R_{FOOD} \right\rfloor & E = 3,4 \\
\left\lfloor \text{工业数} \times K_{IND} / R_{INDPOP} \right\rfloor & E = 5
\end{cases}$

> **编号约定**：此处 $E = 1 \ldots 5$ 为 **1-based 时代编号**。
> 代码 `formulas.js:121` 用 **0-based 下标**，其条件写作 `E <= 1 / E <= 3 / else`，
> 两者换算为「下标 = 编号 − 1」，**但共用符号 E** —— 读代码时务必先确认是哪一套。

**设计意图**：让玩家在每个阶段面对**不同的瓶颈**，而不是"一直堆一种建筑"。
E1–2 逼玩家划居住、E3–4 逼玩家保粮、E5 逼玩家建工业。

### 5.3 世界有限的"硬上限"

岛屿可建造格实测 **4,979~5,881/种子**（半径 ≥94 恒为海洋），叠加 8 邻域空置规则后
建筑地块**硬上限 ≈1,350**。这个约束**驱动了多项设计**：
- 建筑代理比 `BUILD_Q`（1 格 = N 栋）→ `09_数值与公式手册.md §9`
- E5 目标从 10 万下调到 6 万
- 自动建造 `need[]` 用**地块口径**而非逻辑口径
