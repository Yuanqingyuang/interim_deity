## 三、已修复的历史缺陷（含根因）

> 按**根因类型**归类 —— 这比按时间排列更有参考价值，因为同一根因会反复出现。

### 3.1 根因一：口径混淆（逻辑数 vs 地块数）

**这是本项目最高发的缺陷类型**（`BUILD_Q` 引入后尤甚）。

| 缺陷 | 症状 | 根因 |
|---|---|---|
| `housingCap` 漏乘 `BUILD_Q` | E3+ 时 `housingCritical` **恒真** → 自动建造无条件建房、挤占农田名额 | 测试只在 E1（$q_b = 1$）跑过，**该值恰好掩盖了缺陷** |
| `buildSpeed` 收到地块数 | E5 内部供给只有 HUD 的 **1/20**；且奇迹在建时供给恒被减到 0 | 调用点未标明所持口径 |
| 里程碑阈值未换算 | "HUD 说未达标但实际已满足" | `claimMilestones` 入参是地块数，需乘 `buildQ` |
| 进阶门槛口径 | 某些种子**永久停在工业 9/s、12/s**，无法通关 | `gateOf` 是逻辑口径，地块数未乘 `buildQ` |

**防线**：`formulas.js` 调用点注释必须标注口径；测试对两个口径各有专门断言；
`09_2` 文档 §3.6 专门记录此教训。

### 3.2 根因二：判据边界不重合

| 缺陷 | 症状 | 根因 |
|---|---|---|
| 河道长在山顶 | 河道占陆地 34–47.5%，其中 **75–77% 在山地**（占比随高程**单调升高**，6+ 带达 **80%**） | 河道掩码是**纯噪声、无高程约束**（`inland` 项与高程正相关，反把河流推向高地） |
| 河道是干沟 | **57–67%** 的"河道"河床高于水面 | 冲刷公式最多只降到 $0.8h$，对 $h=5$ 只到约 1.3 |
| 旷野暗角跳变 | 一格内亮度跳 **27%**（大世界 35%） | `dim` 按"到包围盒**中心**距离/半跨度"算，而托管/旷野按**格是否存在**判定 |
| 格中心高度错位 | 建筑浮空/埋地约 300 格；平均偏差 0.057–0.068，最大 **0.853** | `_surfaceY` 用 5 点十字均值，网格用四角核 |

**共性**：**两个本该一致的判据各自定义**，边界不重合处即出现跳变。

### 3.3 根因三：状态残留

| 缺陷 | 症状 | 根因 |
|---|---|---|
| `painting` 卡死 | 鼠标一移动就持续扣神力并雕刻地形 | 只监听 `pointerup`；触摸被打断/指针移出窗口/窗口失焦时该事件不触发 |
| 跨时代继续施工 | 新时代表格被继续雕刻；奇迹按钮永久停在"放置中"样式 | `applyEraAdvance` 未清除 `placingWonder`/`painting`/`panning`/`hover` |
| `beforeunload` 监听器丢失 | **桌面端关页/刷新丢档** | 抽 `saveOnExit` 函数时把原监听器替换掉却未重新注册（注册数 1 → **0**） |

**防线**：静态门禁断言监听器注册数（见 `14` 文档 §2.4）。

### 3.4 根因四："假修复"（写了但没生效）

**本项目最危险的一类问题**，共 **4 次**记录，其中 **2 次由 AI 造成**：

| 实例 | 说明 |
|---|---|
| `screenToTile` 的 `_terrainVer` | commit `b783459` 提交信息声称已加，但 `_terrainVer` 在**全部 48 个历史提交中出现 0 次** —— 补丁被静默回退且无人发现 |
| `frustumCulled = true` | 被 3 行后的 `= false` 覆盖 → `computeBoundingSphere` 守卫从未执行 |
| 惰性几何 | 6 个构件因缓存键错误而每次新建，合批失效 |
| `wonderPopMult` 丢失 | 重构中丢失 → 奇迹人口加成只在 autoBuild 压力判断里生效、实际拿不到 |

**防线（本项目最重要的工程实践）**：

| 手段 | 做法 |
|---|---|
| **反向验证** | 每个修复都必须"注入缺陷 → 确认断言失败"，否则无法证明断言有效 |
| **回读验证** | 改完后**读回文件确认内容存在**（"写了但没生效"与"没写"在提交信息上无法区分） |
| **阈值有牙齿** | 容差必须**小于**被测量边界（曾有 `TOL = 0.66 > BLD_EXTENT = 0.46`，断言形同虚设） |
| **禁止恒真断言** | 已清理 `assert(true, …)`、`n === 0 \|\| n >= 1`、`grp.isGroup !== false` |

### 3.5 根因五：与帧率耦合

| 缺陷 | 症状 | 根因 |
|---|---|---|
| 人口崩溃 | 低帧下人口**数秒内从 20 崩到 1**，玩家不知发生了什么 | 缺粮衰减实现为"每 tick 减半"，与帧率强耦合 |
| 城市演化不可复现 | 同种子无法复现同一演化序列 | `autoRng` 依赖 `G.time`（由 `dt` 累加） |

**已修**：人口衰减改为随 `dt` 的连续回落。
**未修**：`autoRng` 的帧率依赖（见 §四）。

### 3.6 根因六：测试与 CI 形同虚设

| 缺陷 | 症状 |
|---|---|
| CI 浏览器回归**长期静默跳过** | 静态服务从**仓库根**起（`index.html` 在 `trainee-deity/`）→ `/index.html` 404；而 `curl -sf … && echo` 探测失败**不影响 job 结论** |
| 打印型测试 | 只 `console.log` 无断言，永远"通过" |
| 4 个浏览器测试无门禁 | 缺 `process.exit`，失败也返回 0 |
| `npm run test:browser` 与 CI 漏跑 2 个测试 | `stress-test`、`platform-test` 未纳入 |

**已修**：全部有真 `process.exit` 门禁；统一入口 `run-browser.mjs` 含服务预检。

## 四、当前已知问题与风险（按严重度）

### 🔴 R-1：零遥测 —— 上线最大未知项

| 项 | 说明 |
|---|---|
| **现状** | 实测 `js/` 内**零网络调用、零统计 SDK**；线上报错只进**玩家自己的控制台** |
| **后果** | 不知道玩家在哪一步流失、哪一步卡住；游戏前 5 分钟劝退率**完全不可见** |
| **为何严重** | 难度曲线只在模拟层验证过"可通关"，**无任何真实玩家数据**。"能通关"与"好玩/不劝退"是两件事 |
| **建议** | 加**最小匿名遥测**（开局 → 首次划地 → 第一个时代 → 各时代耗时 → 流失点），无 PII |
| 判定 | 【待确认】是否属有意设计（单机游戏可合理选择不采集） |

### 🔴 R-2：真实设备未验证

| 项 | 说明 |
|---|---|
| **现状** | 所有帧率数据来自 **Chromium SwiftShader 软件渲染**（无 GPU），实测 2–12 FPS |
| **后果** | 真实移动端 GPU 的帧率、发热、iOS 内存回收表现**完全未知** |
| **加重因素** | 代码专门为 **iOS Safari** 写了 `pagehide` 兜底，说明该路径**被预判为脆弱**，却从未真机验证 |
| **建议** | iPhone Safari + 一台安卓真机各走一遍完整流程 |

### 🟠 R-3：Firefox / WebKit 未实测

| 项 | 说明 |
|---|---|
| **现状** | `platform-test` 矩阵中 `firefox` 与 `webkit` 因**未安装引擎**而 SKIP |
| **后果** | Safari 差异（WebGL、触控、bfcache）最容易踩 |
| **代价** | 小 —— 装两个引擎即可 |

### 🟠 R-4：零冗余星星的脆弱性

| 项 | 说明 |
|---|---|
| **现状** | 每时代恰好 3 个里程碑，`starCost = 3` —— **零冗余** |
| **后果** | **任一里程碑不可达即时代硬锁死**（历史上已发生过一次：里程碑指向上一时代奇迹） |
| **建议** | 要么给 1 星冗余（`starCost = 2`），要么加"里程碑可达性"自动校验 |
| **位置** | `config.js:41 MILESTONES`、`ERAS[].starCost` |

### 🟠 R-5：`autoRng` 依赖帧率 → 城市演化不可复现

| 项 | 说明 |
|---|---|
| **现状** | `autoRng(G, salt)` = `mulberry32(seed + ⌊G.time × 2⌋ × 9973 + salt)`，`G.time` 由 `dt` 累加 |
| **后果** | **地形可复现，但城市演化不可复现**（不同帧率下采样序列不同） |
| **影响** | 不利于 bug 复现与竞速/验证类玩法 |
| **建议** | 把 `G.time` 改为**固定步长累加**（如按 1/30 秒整数计数） |
| **位置** | `config.js:313` |

### 🟡 R-6：无回滚预案

| 项 | 说明 |
|---|---|
| **现状** | 无回滚流程；`dist/` 未保留历史版本 |
| **特殊风险** | **回滚代码不会回滚存档** —— 若新版引入存档结构变更，回滚后旧代码可能读不了新存档 |
| **建议** | 见 `13` 文档 §7.4 |

### 🟡 R-7：`localStorage` 单机模型的玩家知情度

| 项 | 说明 |
|---|---|
| **现状** | 换设备/清缓存即丢档；无云备份；无存档校验和；无备份轮转 |
| **建议** | 在页面或部署文档**明确提示**；`saves.js` 已有 JSON 导出/导入功能但**玩家多半不知道** |

### 🟡 R-8：`hash2` 精度问题

| 项 | 说明 |
|---|---|
| **现状** | 乘法中间结果超 $2^{53}$（JS 整数安全上限），位混合**有损** |

### 6.2 ⚠️ 编号陷阱（重要）

| 场景 | 基数 | 取值 |
|---|---|---|
| 规格文档、公式 | **1-based 编号** | $E = 1 \ldots 5$ |
| 代码（`G.era`、数组下标） | **0-based 下标** | `era = 0 … 4` |

**换算**：$\text{下标} = \text{编号} - 1$

**经典陷阱**：`formulas.js:121 popCap()` 写作 `if(E <= 1) / else if(E <= 3) / else`，
其中 `E` 是**下标**，对应编号 $E \le 2$ 与 $E \le 4$。
规格 `§3②` 却写作 `E ≤ 2 / 3 ≤ E ≤ 4`（编号）。**语义一致但符号相同。**

| **合批 / InstancedMesh** | 用一次 draw call 绘制多个相同几何+材质的对象 |
