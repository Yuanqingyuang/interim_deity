### 1.1 为什么"无打包器"是重要架构决策

```
index.html 内的 importmap：
{
  "imports": {
    "three": "./vendor/three@0.161.0/three.module.js",
    "three/addons/": "./vendor/three@0.161.0/examples/jsm/"
  }
}
```

**收益**
- 部署 = 复制文件，无需构建步骤
- 浏览器原生 ESM，调试时错误行号直指源文件
- 完全离线可玩（无 CDN）

**代价与应对**
- ⚠️ **Node 读不到 importmap** → 任何 `import render.js` 的 Node 测试会解析失败
  → 应对：`test/support/ensure-three-shim.mjs` **按需**把 `vendor/` 复制到 `node_modules/three/`
  （不改 vendor 原件、不联网、不装 npm 包；干净检出后首次跑测试自动生成）
- ⚠️ **无构建哈希** → 必须 `Cache-Control: no-cache`，否则改版后老用户仍跑旧代码
  （实测踩过：浏览器仍用旧 `styles.css` 与 `saves.js`）

### 3.1 依赖方向原则【已实现】

- **依赖严格单向**，无环：`config → formulas → {state, terrain, autobuild} → {render, progression, savepolicy} → main → ui`
- `config.js` **零内部依赖**，是稳定的地基
- 三个"纯决策"模块（`progression` / `savepolicy` / `autobuild`）**只依赖 `config` + `formulas`**，
  **不接触 DOM / 渲染 / localStorage** → 因此可被 Node 直接单测

> **这是一条刻意的架构约束**：`main.js` 顶层会 `boot()` 并注册 `window` 监听，
> 故 **Node 无法 import 它**。凡是想被单测覆盖的决策逻辑，都必须抽到纯模块。
> 2026-10 的三次重构（`progression` / `savepolicy` / `autobuild`）都是为此。

### 4.1 `config.js` —— 全局常量与调参中心

| 项 | 内容 |
|---|---|
| 职责 | 集中所有可调数值，避免散落 |
| 关键导出 | `APP_VERSION`、`TILE`、`MAXH/MINH/WATER_LEVEL`、`ERAS`、`MILESTONES`、`AUTO`、`TOOLS`、`MIRACLES`、`WONDERS`、`PALETTES`、`BUILDING_STYLE`、`CHURCH_STYLE`、`FACTORY_STYLE`、`SUN_KEYS`、`DAY_LENGTH`、`CHUNK`、`WILD`、`FOG_*`、`MAX_*_MESH`、`FAITH_ERA_DAMP`、`FAITH_ERA_BASE`、`FAITH_CAP_MULT`、`powerMaxOf`、`powerRegenOf`、`faithCapOf`、`sampleSun`、`lerpHex`、`hash2`、`mulberry32`、`formForEra`、`churchStyleForEra`、`factoryStyleForEra` |
| 依赖 | 无 |

**文本描述代码功能**：
这是整个游戏的"数值配置面板"。它定义：世界的基本单位（地块边长 1.0、地形高度范围 0.2–9、
水面高度 0.75）；五个时代各自的名称/罗马数字/人口目标/星星消耗；每时代三个里程碑及其判定条件
（里程碑以闭包 `check(G, ctx)` 形式内联，便于携带上下文）；自动建造的间隔与压力阈值；
十种玩家工具的消耗与半径；三种神迹的消耗与持续秒数；五座世界奇迹的信仰消耗与加成文案；
五套时代调色板（地表/水/天空/雾/建筑配色）；四类建筑的形体描述表（`form` 字段驱动渲染分支）；
日照关键帧表（用于插值出一天的太阳高度/方位/光强/色温）；以及一组确定性哈希/噪声工具函数
（`hash2`、`mulberry32` —— **禁止使用 `Math.random`，以保证同种子同世界**）。

### 4.2 `formulas.js` —— 数值公式（唯一权威实现）

| 项 | 内容 |
|---|---|
| 职责 | 承载全部数值公式，与 `numeric-design.md` 对齐 |
| 关键导出 | `T`、`NUM`、`LAYOUT`、`eraIndex`、`buildingLow/High`、`buildQ`、`toTiles`、`buildingLowTiles/HighTiles`、`wonderPopMult`、`popCap`、`foodPerSec`、`foodNeed`、`faithPerSec`、`industryPerSec`、`gateOf`、`growPop`、`buildSpeed`、`wonderDrawPerSec`、`renderVillagers` |
| 依赖 | `config.js` |

**文本描述代码功能**：
把策划案里的每个公式翻译成一个纯函数。核心是维护**两套口径**并明确区分：
"逻辑建筑数"（用于产出/人口上限/里程碑）与"地块数"（用于放置目标/地图硬上限），
两者通过建筑代理比 `BUILD_Q` 互转。提供人口上限的分阶段主导计算、粮食与信仰与产能的产出计算、
时代进阶的产能门槛、人口增长的指数增长 + 缺粮连续衰减、建造速度的"供给÷需求比"模型、
以及村民渲染数量的线性代理映射。**所有函数都是纯函数**（无副作用、不读全局），
因此可被 Node 直接单测 —— 这是本项目测试覆盖率最高的模块。

### 4.3 `state.js` —— 世界状态与空间查询

| 项 | 内容 |
|---|---|
| 职责 | 地块数据结构、区块索引、空间查询、统计缓存 |
| 关键导出 | `makeTile`、`chunkKey`、`worldToChunk`、`getTile`、`tileLive`、`eachTile`、`eachChunk`、`chunkBounds`、`createState`、`countBuilt`、`countZone`、`housingCap`、`foodCap`、`faithMult`、`refreshBuiltCache`、`invalidateBuiltCache`、`serializeState(Async)`、`deserializeState` |
| 依赖 | `config.js`、`formulas.js`、`log.js` |

**文本描述代码功能**：
维护"无限世界"的数据表示。世界被切成 10×10 的**区块**，每个区块持有一个长度为 100 的
**地块数组**（线性排列，非 Map —— 这点在写遍历代码时极易踩坑）。提供按世界坐标查地块
（`getTile`，越界返回 `null`）、遍历所有已生成地块（`eachTile`）、计算所有区块的包围盒
（`chunkBounds`）等查询。同时维护两个**统计缓存**：已划定数（`_zoneCache`）与已建成数
（`_builtCache`），避免每帧全图扫描；两者由 `invalidateBuiltCache` 统一失效。
还负责存档的序列化与反序列化（含 v1/v2/v3 版本迁移与字段夹取消毒）。
`housingCap` 是 autoBuild 判断"住房是否仍是瓶颈"的**代理量**（恒为住房×容量×奇迹加成），
与 `popCap` 的基数不同，这是刻意的。

### 4.4 `terrain.js` —— 地形生成与放置规则

| 项 | 内容 |
|---|---|
| 职责 | 程序化地形、河道、地形改造、区域放置的全部规则 |
| 关键导出 | `heightAt`、`sampleHeight`、`riverMask`、`WATER_PLANE_Y`、`RIVER_THRESHOLD`、`terrainClass`、`genWorld`、`ensureChunk(Ring)`、`placeAt`、`applyTool`、`canPlaceZoneManual/At`、`zoneNeedsGap`、`placeDistrict`、`placeIndustryBatch`、`findAutoSite`、`scoreIndustrialCell`、`tileIndex`、`residentialStats`、`cornerColor`、`clearTreesNearZones`、`cornerHeightAt` |
| 依赖 | `config.js`、`state.js` |

**文本描述代码功能**：
这是"世界如何长出来"与"什么能放在哪里"的全部逻辑。地形由**多层噪声**合成：
一个大陆场决定海陆（径向衰减，故岛屿半径 ≥94 处恒为海洋）、ridged/fbm 噪声塑造山脊、
一层**河谷包络**把河道限制在低地（否则河流会长在山顶）、以及河道冲刷把河床切到水面之下。
提供连续采样（`heightAt` 不含河、`sampleHeight` 含河冲刷）与离散化到地块两种接口。
放置规则的核心是 **「8 邻域空置」**：非农田建筑要求周围 8 格全空，这条规则把非农田密度
压到 ≤25%，是全项目多处设计约束的源头。选址用**打分场**：对候选格按到居住区距离、
邻接同类数、地形平整度等加权打分取最优；工业还有"距居住最小切比雪夫距离 = 6"的硬约束。
`tileIndex` 是按"地图变更版本号"缓存的**地块索引**，把 autoBuild 一轮内原本 4 趟全图扫描
合并为 1 趟。`cornerColor` 是顶点着色（沙滩→草→深草→岩→雪五段，段界连续）。

### 4.5 `render.js` —— Three.js 渲染层

| 项 | 内容 |
|---|---|
| 职责 | 场景、地形网格、建筑构建器、合批、光照、粒子、村民 |
| 关键导出 | `Renderer`（类）、`cornerHeightAt` |
| 依赖 | `three`、`config.js`、`terrain.js`、`state.js`、`formulas.js` |

**文本描述代码功能**：
**本项目最复杂的模块（126 KB）**。它做四件事：

① **地形网格**：全世界**一张** `BufferGeometry`（非每区块一张），顶点由全局 `ox/oy/W/H` 生成，
每格中心高度 = 四角均值（=`1/16 × [1,2,1]⊗[1,2,1]` 核），颜色用顶点色。
② **建筑构建器**：`makeBuilding()` 按「分区 × 时代」分派到 20 套形体函数（住房五型、农田五型、
工业五型、教堂五型），每套由若干共享几何拼装。**硬约束：`_make*` 内禁止 `new THREE.*`** ——
所有几何/材质必须取自 `_geo` / `_matCache` 缓存，否则会被逐栋创建、破坏合批前提。
③ **性能合批**：已完工建筑按「(几何, 材质, 是否投影)」聚合为 `InstancedMesh` 槽位
（实测 4,172 栋 → 275 DrawCall）；建造中建筑仍走独立 Group（需要逐栋进度缩放）；
村民按身体部件聚合为 6 个 `InstancedMesh`；树木同理。
④ **光照与氛围**：按 `SUN_KEYS` 关键帧插值出一天的太阳/半球光/环境光/雾色；
阴影用 PCF，正交框跟随城区中心与半径（`far/near` 也随之派生）；天空为 Canvas 渐变 +
夜间星点；云为单平面 + 平铺贴图（`MeshBasicMaterial` 需手动按昼夜着色）；水面为
单平面 + 波纹滚动贴图，高度 = `WATER_PLANE_Y`。

还包含拾取（`screenToTile`，带两级缓存：整条射线相同 → 复用；否则用射线与地平面求交
算出近似格号作闸门）、悬停高亮环、粒子（建筑落成/时代进阶的爆散）、
以及完整的资源释放（`dispose()` 释放几何/材质/贴图/实例缓冲并解绑监听）。

### 4.6 `main.js` —— 编排层（主循环与副作用）

| 项 | 内容 |
|---|---|
| 职责 | 游戏主循环、输入处理、事件编排、UI 刷新、生命周期 |
| 关键导出 | `milestoneSummary`（转发） |
| 依赖 | 几乎全部模块 |

**文本描述代码功能**：
**唯一把各模块"接起来"的地方**，但本身尽量不含决策逻辑。它负责：
`boot()`（启动序列：生成世界 → 建地形 → 建水面 → 同步场景 → 显示界面）；
`loop()`（`requestAnimationFrame` 主循环，`dt` 钳制到 0.05s 上限以防切回标签页时补算巨量时间；
按 `speed` 倍率加速经济但不影响昼夜）；`tick()`（经济推进：产出入账、人口增长、建造进度、
里程碑检查、按 0.1s 节流标记地形脏）；输入处理（鼠标/触摸的按下/移动/抬起，注意
`touchcancel` 与 `window blur` 也会复位，否则 `painting` 会卡住导致持续扣神力）；
三条存档路径的接线（周期自动存档、离场同步写、转后台异步写，决策在 `savepolicy.js`）；
以及全局错误兜底（`error` / `unhandledrejection` 转成玩家可见提示）。

**关键工程约束**：本模块顶层直接执行 `boot()` 并注册 `window` 监听，
因此 **Node 无法 import 它**。凡需单测的逻辑都已抽到 `progression` / `savepolicy` / `autobuild`。

### 4.7 `autobuild.js` —— 子民自动建造决策【纯逻辑】

| 项 | 内容 |
|---|---|
| 职责 | 决定"本轮该建什么、按什么优先级" |
| 关键导出 | `buildNeeds`、`pendingWeight`、`buildGates`、`buildOrder`、`autoBuildDecision` |
| 依赖 | `formulas.js` |

**文本描述代码功能**：
纯决策函数集合，**不接触世界也不产生副作用**。输入是当前的"划定数/已建成数/人口/住房上限/
信仰产出"，输出是"本轮的行动顺序列表 + 是否紧急 + 兜底标志"。
它承载两个真实玩法灾难的修复：**S-04 棘轮**（目标值必须在达标后归零，不能写成 `数量+2`，
否则缺口判定恒真会无脑刷满全岛）与**住房死锁**（房屋要求 8 邻域全空，若名额被农田/工业
占掉则第一栋房永远建不出，人口会卡死）。
`buildNeeds` 算目标地块数、`buildGates` 算粮食/产能/住房/教堂四类缺口、
`buildOrder` 给出优先级、`autoBuildDecision` 一次性算出全部。

| 项 | 内容 |
|---|---|
| 职责 | 进阶条件判定、里程碑结算、进阶状态迁移 |
| 关键导出 | `eraReadiness`、`eraReady`、`claimMilestones`、`milestoneSummary`、`applyEraAdvance` |
| 依赖 | `config.js`、`formulas.js` |

**文本描述代码功能**：
把"能否进入下一时代"拆成四项可独立检查的条件（人口、本时代奇迹、星星、产能门槛），
并返回**具体缺哪项**（而不是简单的布尔），便于 UI 提示与排障。
里程碑结算负责把新达成的项置位、加星，并返回"新达成列表"让调用方去弹提示
（表现层不在这里）。进阶迁移只改状态字段（扣星、`era+1`、清掉"放置中/雕刻中"的残留输入态），
渲染刷新与音效由调用方执行。
**注意**：进阶条件的产能门槛必须用**逻辑口径**（地块数 × `buildQ`），
传错会让后期少算 20 倍。

### 4.9 `savepolicy.js` —— 存档节流与互斥【纯逻辑】

| 项 | 内容 |
|---|---|
| 职责 | 三条存档路径的"是否该写"判定 |
| 关键导出 | `isSaveBusy`、`autosaveTick`、`exitSaveTick`、`bgSaveTick` |
| 依赖 | 无 |

**文本描述代码功能**：
三条存档路径（每 180 游戏秒的周期存档、关页/切后台时的离场同步写、转后台时的异步分块写）
原先各自把"是否该写""节流窗口""互斥条件"写死在事件回调里。此模块把三者统一：
一个共用的"是否有存档正在写"判据（原先各路径检查不同的标志组合，导致漏项 ——
自动存档在飞时切后台会并发两份全量序列化），以及各自的到点判定。
**一个易错细节**：周期存档因"忙"而跳过时**不得清零累加器**，否则这次到点被白白吞掉、
要再等完整一个周期。

### 4.10 `saves.js` —— 存档持久化

| 项 | 内容 |
|---|---|
| 职责 | localStorage 读写、配额回收、异步分块、导入导出 |
| 关键导出 | `SLOTS`、`SLOT_LABEL`、`sanitizeMeta`、`listSaves`、`readMeta`、`writeSave`、`writeSaveAsync`、`readSave`、`deleteSave`、`exportSaveJson`、`importSaveJson`、`yieldToMain` |
| 依赖 | `state.js` |

**文本描述代码功能**：
封装 `localStorage` 的全部操作。有 3 个手动槽位 + 1 个快速档。
写入失败（配额满/序列化失败）**返回 `null`** 而非抛错，调用方必须检查 ——
这是"静默丢档"的防线。提供**配额回收**（清理旧数据后重试）与**超限裁剪重试**。
`writeSaveAsync` 是分块异步写：把序列化切成多块，每块之间 `yieldToMain()` 让出主线程，
避免大图（数 MB）同步 stringify 卡帧；用**槽位序号**实现"最新者获胜"，
使在飞的旧异步写自动放弃提交（无需复杂互斥）。
导入导出为 JSON，导入时经 `sanitizeMeta` 白名单消毒（存档是不可信输入）。

### 4.11 `auth.js` —— 本地账号

| 项 | 内容 |
|---|---|
| 职责 | 多用户注册/登录/会话，密码哈希 |
| 关键导出 | `getUser`、`getUsername`、`register`、`login`、`logout`、`hasUsers` |
| 依赖 | 无（仅 Web Crypto） |

**文本描述代码功能**：
纯本地多用户系统（无后端）。密码哈希走**两条路**：安全上下文（HTTPS/localhost）下用
`crypto.subtle` 的 **PBKDF2-SHA256**；非安全上下文下 `crypto.subtle` 不可用，
降级为 **FNV-1a 弱哈希** —— 并在存档中**如实标注 `kdf: 'FNV-1a-weak'`**、
在 console 明确告警，**绝不冒充强哈希**。读取时按记录的 `kdf` 标签走对应验证路径，
因此旧档可正常登录。会话存于 `sessionStorage`（标签页级）。

|---|---|

## 五、数据流

### 5.1 每帧数据流（`requestAnimationFrame`）

```
loop(now)
 ├─ rawDt → dt（钳制 ≤ 0.05s）
 ├─ wdt = paused ? 0 : dt          ← 昼夜/时间用
 ├─ gdt = dt × speed                ← 经济用
 ├─ 相机按键处理
 ├─ tick(gdt)
 │   ├─ 产出入账（粮/产/信仰）      ← 按「已建成」计，逻辑口径
 │   ├─ growPop()                    ← 人口增长 + 缺粮衰减
 │   ├─ 建造进度推进（buildSpeed）
 │   ├─ 完工判定 → invalidateBuiltCache
 │   ├─ checkStarMilestones()
 │   ├─ tryAutosave(dt)              ← savepolicy 决策
 │   └─ terrainDirty 节流标记
 ├─ 地形重建（若 dirty，0.1s 节流）
 ├─ syncWorld(G)                     ← 建筑/树/村民入场景或批次
 ├─ updateDayLight / updateWater / updateClouds / 粒子 / NPC
 ├─ updateUI()（0.1s 节流）
 └─ renderer.render()
```

### 5.2 建造数据流

```
玩家点击/拖拽
  → ui.js 事件 → main.js handleDown/handleMove
  → render.screenToTile() 屏幕坐标 → 地块坐标
  → main.applyTool() → terrain.applyTool()/placeAt()
  → 修改 t.zone / t.h → invalidateBuiltCache()
  → 下一帧 syncWorld 感知变化
  → 建筑从「建造中」Group → 完工后进入 InstancedMesh 批次
```

### 5.3 存档数据流

```
写：G → state.serializeState()（分块/压缩编码）→ saves.writeSave()
     → localStorage[`td/saves/<user>/<slot>`]
读：localStorage → saves.readSave() → state.deserializeState()
     （版本迁移 v1/v2→v3、字段夹取消毒）→ 替换 G → 重建场景
```

## 六、架构上的关键取舍（供移植参考）

| 决策 | 理由 | 移植时的注意点 |
|---|---|---|
| 无打包器、源码直出 | 部署零构建、调试直观 | 其他引擎需另建构建流程；注意 `importmap` 是浏览器特性 |
| 世界一张地形网格 | 天然无区块裂缝（共享顶点） | 区块制的引擎需自行处理接缝 |
| 逻辑数与地块数双口径 | 世界格子有限但逻辑规模可大 | 移植时必须同步明确"哪些量是逻辑、哪些是格子" |
| `_geo`/`_matCache` 共享池 | 合批前提（按几何+材质聚合） | 若引擎支持自动实例化，此约束可放宽 |
| 决策逻辑抽成纯模块 | 让 Node 可单测（顶层 `boot()` 的模块无法 import） | 任何引擎都受益于此分层 |
| 顶栏/面板全 DOM 而非 Canvas UI | 便于复用与无障碍 | 3D 引擎内的 UI 方案需另选 |
| 程序生成全部贴图/音效 | 零美术资源依赖、包体小 | 换取的是美术表现上限较低 |
