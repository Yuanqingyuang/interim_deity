## 一、界面结构

### 1.1 三层分工

| 层 | 实现方式 | 职责 |
|---|---|---|
| **3D 场景** | Three.js Canvas | 世界、地形、建筑、村民、天空、水、粒子 |
| **HUD / 面板** | **原生 DOM + CSS** | 顶栏读数、工具栏、存档对话框、toast |
| **输入** | Canvas 事件 + 键盘 | 鼠标/触摸绘制、相机操作、快捷键 |

> **设计决策**：HUD 用 DOM 而非 Canvas 绘制。
> 收益：文本可选中、可访问性（aria 属性）、样式易调、无需自绘文字。
> 代价：与 3D 的层级/穿透需手动协调（如画布上的指针事件不能挡住 DOM 面板）。

## 二、顶栏读数（HUD）

### 2.1 读数字段

【已实现】`js/ui.js`，刷新节流 **0.1 秒**

| 字段 | 数据源 | 口径 |
|---|---|---|
| 时代徽标 | `ERAS[G.era].roman + name` | — |
| 神力 | `G.power` / `powerMaxOf(era)` | 存量 |
| 信仰 | `G.faith` / `faithCapOf(era)` | 存量（带上限） |
| 人口 | `G.pop` / `popCap(...)` | 绝对人口 |
| 粮食 | `foodPerSec(farms × buildQ(era))` / `foodNeed(pop)` | 流量 |
| 产能 | `industryPerSec(inds × buildQ(era))` / `gateOf(era)` | 流量 + 门槛 |
| 星标 | `G.stars` | — |
| 版本角标 | `APP_VERSION` | — |

### 2.2 ⚠️ 口径一致性（重要）

**HUD 显示的所有建筑相关读数必须用逻辑口径**（地块数 × `buildQ(E)`），
与 tick 内部控制计算同源。

**历史上因口径不一致造成的玩家可见问题**：

| 问题 | 症状 |
|---|---|
| `buildSpeed` 收到地块数 | E5 内部供给只有 HUD 的 **1/20** → 玩家看到产能充足但建造极慢 |
| `housingCap` 漏乘 `BUILD_Q` | 自动建造无条件建房、挤占农田 → 玩家看到"该建农田却一直建房" |
| 里程碑阈值未换算 | "HUD 说未达标但实际已满足" |

**防线**：`ui.js` 的读数与 `main.js` tick、`progression.js` 判定
**共用同一套 `formulas` 函数**，且测试对里程碑换算有专门断言。

## 三、输入系统

### 3.1 鼠标 / 触摸事件

【已实现】`js/ui.js` 绑定，`js/main.js` 处理

| 事件 | 行为 |
|---|---|
| `pointerdown` 左键 | 开始绘制（`painting = true`）或放置奇迹 |
| `pointermove` | 绘制中持续作用；非绘制时更新悬停高亮环 |
| `pointerup` | 结束绘制 |
| `pointerdown` 右键 / 中键 | 相机平移（`panning = true`）；**阻止默认菜单** |
| 滚轮 | 缩放（OrbitControls） |
| **`touchcancel`** | **复位 `painting`** ← 见 §3.2 |
| **`window blur`** | **复位 `painting` / `panning`** |
| **`document mouseleave`** | **复位 `painting` / `panning`** |

### 3.2 ⚠️ 三类"复位"事件（2026-10 修复）

**问题**：仅监听 `pointerup` 会在以下情形**卡住 `painting`**：

| 情形 | 后果 |
|---|---|
| 触摸被系统打断（来电、手势返回） | `pointerup` 不触发 → `painting` 永久为真 |
| 指针移出窗口后松开 | 同上 |
| 窗口失焦（Alt+Tab） | 同上 |

**卡住的后果**：鼠标一移动就**持续扣神力并雕刻地形** —— 玩家会看到神力莫名流失、地形被划花。

**修法**：`ui.js` 同时监听 `touchcancel`、`window blur`、`document mouseleave`，
统一调用复位逻辑。

**同类问题**：`progression.applyEraAdvance()` 也必须清除 `painting` / `panning` /
`placingWonder` / `hover`（详见 `08_时代进阶与里程碑.md §4.2`）。

### 3.3 键盘快捷键

【已实现】`main.js _keyBindings`（记录绑定以便统一解绑）

| 键 | 行为 |
|---|---|
| `Space` | 暂停 / 继续 |
| `1`–`4` | 依次选择四类划区工具 |
| `Esc` | 取消当前操作（放置奇迹 / 绘制） |
| 其他（见源码） | 速度倍率等 |

> **工程要点**：`_keyBindings` **记录了绑定关系**，用于页面卸载时统一解绑，
> 避免"重复注册监听导致快捷键响应多次"。

## 四、渲染管线

### 4.1 每帧顺序

```
loop(now)                                    [requestAnimationFrame]
 ├─ rawDt → dt（钳制 ≤ 0.05s）               ← 防切回标签页补算巨量时间
 ├─ wdt = paused ? 0 : dt                    ← 昼夜用
 ├─ gdt = dt × speed                         ← 经济用（可加速）
 ├─ 相机按键处理
 ├─ tick(gdt)                                经济推进
 ├─ 地形重建（若 terrainDirty，0.1s 节流）
 ├─ syncWorld(G)                             建筑/树/村民入场景
 ├─ updateDayLight(wdt)                      日照插值
 ├─ updateWater / updateClouds / 粒子 / NPC
 ├─ updateUI()（0.1s 节流）
 └─ renderer.render()
```

**两级时间步**（重要设计）：

| 时间 | 变量 | 受速度倍率影响 | 受暂停影响 |
|---|---|---|---|
| 昼夜 | `wdt` | ✖ 不受 | ✔ 受影响 |
| 经济 | `gdt` | ✔ × `speed` | ✔ 受影响 |

即：**加速游戏不会让昼夜变快**（否则玩家会看到日夜飞速交替）。
浏览器测试有一条专门断言："暂停时画面仍变化（光照/云未冻结）"。

### 4.2 地形网格

| 项 | 实现 |
|---|---|
| 网格数 | **全世界一张** `BufferGeometry`（非每区块一张）→ **区块间无裂缝** |
| 顶点 | 由全局 `ox/oy/W/H` 生成，每格中心高度 = 四角核（见 `09_2` 式 43/44） |
| 颜色 | **顶点色**（`cornerColor`，五段连续） |
| 索引 | `Uint32Array` 按 `W/H` 缓存，**尺寸不变时零分配**（原实现每次重建 ~2 MB） |
| 重建节流 | `terrainDirty` 标记 + 0.1s / 0.15s 间隔 |
| 版本号 | 每次重建递增 `_terrainVer`，使**拾取缓存失效** |

### 4.3 建筑合批（性能核心）

【已实现】`render.js`

**双轨设计**（由建造进度决定）：

| 状态 | 渲染方式 | 原因 |
|---|---|---|
| **建造中**（`built = false`） | 独立 `Group`（逐栋） | 需按 `prog` 做**各不相同的缩放动画**，无法合批 |
| **已建成**（`built = true`） | **`InstancedMesh` 批次** | 几何/材质/投影一致 → 可合批 |

**批次键**：`(几何, 材质, castShadow, receiveShadow)`

**硬约束**：`render.js` 的 `_make*` 系列函数内**禁止 `new THREE.*`** ——
所有几何与材质必须取自共享缓存：

```js
this._geo    // 几何缓存（82 个键）
this._matCache  // 材质缓存
```

**违反后果**：每次调用都创建新几何 → 每栋建筑一个批次 → **合批完全失效**。

> 【已实现】曾发生"惰性几何"回归：6 个构件因缓存键错误而**每次新建**，
> 导致批次数量激增。已修复并有断言覆盖。

**实测性能**（P2/P3 压测，Chromium SwiftShader 软渲染，1366×768）：

| 场景 | 建筑数 | DrawCall |
|---|---|---|
| 未合批（基线） | 6,352 | — |
| **P3 合批后** | **4,172** | **275** |
| 浏览器测试实测（E4 满图） | — | 51–56 |

### 4.4 树木与村民合批

| 对象 | 实现 |
|---|---|
| 树 | `InstancedMesh`，每区块上限 `MAX_TREE_MESH = 800`（超出按步长抽样） |
| 村民 | **6 个** `InstancedMesh`（按身体部件），上限 `MAX_NPC_INST = 400` |

### 4.5 光照与氛围

| 元素 | 实现 |
|---|---|
| 太阳/环境/半球光 | 按 `SUN_KEYS` 关键帧插值（`sampleSun`），颜色用 `lerpHex` |
| 阴影 | PCF 软阴影；正交框跟随城区中心与半径，`far/near` 派生 |
| 天空 | **Canvas 渐变贴图** + 夜间星点（程序生成，无图片资源） |
| 云 | 单平面 + 平铺贴图；因用 `MeshBasicMaterial`，**需手动按昼夜着色** |
| 水 | 单平面 + 波纹滚动贴图，高度 = `WATER_PLANE_Y = 0.71` |
| 粒子 | 建筑落成 / 时代进阶 / 神迹的爆散 |

### 4.6 屏幕拾取（`screenToTile`）

【已实现】两级缓存设计（2026-10 重做）

| 层级 | 判据 | 命中条件 |
|---|---|---|
| **第一级** | 射线完全相同 | 鼠标未移动 → 直接复用上次结果 |
| **第二级** | **地平面求交算出的近似格号**（`gx/gy`）+ 相机键（`camKey`）+ 地形版本（`_terrainVer`） | 近似格号未变且相机/地形未变 |

**实测效果**：同一格内移动 30 次 → **1 次 raycast**（原为 30 次）；跨格移动 30 次 → 30 次；
地形版本变化时**正确失效**。

> ⚠️ **本项目最严重的一次"假修复"记录**：commit `b783459` 的提交信息声称
> `screenToTile` 加了地平面闸门与 `_terrainVer`，但 `_terrainVer` 在**全部 48 个历史提交中出现 0 次**
> —— 补丁被静默回退且无人发现。
> 后在 `82c92b9` 重做，并**加入回读校验**（改完后读回文件确认内容存在）。
> 教训：**改完必须回读验证**，不能只信提交信息。
