# 核实更正 · 「人口 0 空城吸收态」**不存在**（2026-10-11 复核）

> 本文更正文档集中的一处**事实错误**。原文由我（同一会话的 Web 侧整理者）撰写，
> 依据是**直接调用 `formulas.growPop()`** 的探针结果，但**没有走 `main.js` 的 tick 主循环**，
> 而主循环在 `growPop` 之后还有一步钳制被我漏掉了。

## 二、实测证据（决定性）

`01_WebDemo/js/main.js` 的 `tick(dt)` 末尾：

```js
const cap = F.popCap(E, housesL, farmsL, indsL, G.wonders);
let nextPop = F.growPop(G.pop, cap, E, farmsL, dt);
if(G.boostGrow>0) nextPop = Math.min(cap, G.pop + (nextPop-G.pop)*2 + 0.6*dt);
G.pop = Math.max(1, nextPop);      // ← 就是这一行
```

**`G.pop = Math.max(1, nextPop)`** —— 人口在**主循环层**被钳制到 **≥ 1**。

我此前的探针只调用了纯函数 `growPop()`（其返回值下限是 `Math.max(0, next)`），
因此测出「0 是吸收态」。**但游戏运行时根本不会把 0 写回 `G.pop`** ——
`growPop` 的返回值先经过 `Math.max(1, ·)`。

### 两个函数的契约差异（这才是需要记录的事实）

| 函数 | 返回值下限 | 说明 |
|---|---|---|
| `formulas.growPop(...)` | **0** | 纯函数，只负责「按公式算出下一个值」 |
| `main.js` tick 写回 `G.pop` | **1** | 主循环额外的业务钳制 |

**所以：「吸收态」是纯函数层的性质，不是游戏的运行时行为。**

### 缺粮时到底会怎样（正确描述）

人口衰减到 **1** 并在 1 停住；玩家划一块农田（粮产 > 0）后人口立即回升。
不存在「永久卡死」，也**不存在需要加下限的缺陷**（下限已经存在）。

## 三、对 Unity 移植的影响（重要）

| 项 | 结论 |

| Unity 侧 `GrowPop` 的返回值 | 应与 Web 纯函数一致（下限 0），**钳制放在 tick 编排层** |

## 四、我从这个错误里得到的教训（供后续 Agent 参考）

1. **纯函数探针 ≠ 运行时行为。** 验证游戏规则必须走**真实调用链**（或在探针里补上主循环的收尾步骤），否则会把「函数返回值范围」误报成「游戏状态」。
2. 这类错误的特征是**结论看起来非常合理**（公式确实会退化到 0），所以更难自查。反例检查应问一句：**「这个值最终是谁写回状态的？」**
3. 原文在 `18` 文档里还给了三种修法建议——**三种都不需要**，因为问题不存在。已在该文档标注更正。
