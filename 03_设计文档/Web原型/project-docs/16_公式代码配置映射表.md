### 0.3 ⚠️ 全局口径约定（读表前必看）

$$\text{式} \xrightarrow{\text{口径}} \begin{cases}
\textbf{逻辑数} & \text{产出 / 人口上限 / 里程碑 / 进阶门槛} \\
\textbf{地块数} & \text{放置目标 / 地图硬上限}
\end{cases}$$

$$\text{地块数} = \left\lceil \frac{\text{逻辑数}}{q_b(E)} \right\rceil, \qquad q_b(E) = \text{BUILD\_Q}[E] = [1,1,3,6,20]$$

**编号约定**：本文档公式用 **1-based 时代编号** $E = 1 \ldots 5$；
代码用 **0-based 下标** `era = 0 … 4`。换算：$\text{下标} = \text{编号} - 1$。

### 4.1 ⚠️ `buildSpeed` 的混合口径（式 26，本项目最易错处）

```js
export function buildSpeed(E, industries, pending, wonderDraw = 0){
  //                          ↑ 逻辑数      ↑ 地块数
  const supply = industryPerSec(industries) - wonderDraw;   // 逻辑口径
  const demand = pending * NUM.C0 * Math.pow(1.5, E);       // 地块口径
}
```

| 参数 | 口径 | 原因 |
|---|---|---|
| `industries` | **逻辑数** | 走 `industryPerSec`（产能产出用逻辑口径） |
| `pending` | **地块数** | 与 `BUILD_COST` 权重相乘 → 表示"格子工作量" |

**历史缺陷**：曾传地块数给 `industries` → E5 内部供给只有 HUD 的 **1/20**。

### 4.2 ⚠️ 进阶门槛的口径（式 31）

```js
// progression.js eraReadiness —— 那行 * buildQ 是硬锁事故的高发点
const indTiles   = (G._builtCache && G._builtCache[3]) || 0;
const indLogical = indTiles * F.buildQ(era);        // ← 必须换算
const indPerSec  = F.industryPerSec(indLogical);
const gate       = F.gateOf(era);                   // 逻辑口径
```

**历史缺陷**：未换算 → 某些种子**永久停在工业 9/s、12/s**，无法通关。
