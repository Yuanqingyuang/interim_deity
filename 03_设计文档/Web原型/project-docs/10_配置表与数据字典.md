## 〇、关于"配置表"

### 0.1 本项目**没有**外部配置表

【不适用】本项目**不存在** Excel / CSV / JSON 配置文件。

所有配置以 **JS 常量对象内嵌**在 `js/config.js` 与 `js/formulas.js` 中。
原因：本项目采用「无打包器、源码直出」架构（见 `02` 文档 §1.1），
引入外部表格需要额外的解析与构建步骤，与架构目标冲突。

| 常见配置表形式 | 本项目状态 |
|---|---|
| Excel `.xlsx` | 【不适用】无 |
| CSV | 【不适用】无 |
| JSON 配置 | 【不适用】无（存档是 JSON，但那是**数据**不是**配置**） |
| YAML | 【不适用】无（CI 用 YAML，与游戏配置无关） |
| **JS 常量模块** | ✔ **本项目采用** |

### 0.2 配置的"加载方式"

【已实现】通过 ES Module 静态导入，浏览器原生解析：

```js
// js/formulas.js
import { FAITH_ERA_DAMP } from './config.js';

// js/autobuild.js
import * as F from './formulas.js';
```

| 特性 | 说明 |
|---|---|
| 加载时机 | 页面加载时由浏览器 ESM 加载器解析（无运行时读取） |
| 依赖顺序 | `config.js` **零内部依赖** → 最先加载，是稳定的地基 |
| 可否热改 | **否**。改配置需改源码并刷新页面 |
| 可否运行时调参 | 部分可以：`?debug=1` 下暴露的压测探针可改部分运行时状态 |
| 校验 | 无 schema 校验；靠测试断言（如 `r16-build-q.test.mjs` 校验 `BUILD_Q` 预算） |

### 0.3 修改配置的注意事项（重要）

| 风险 | 说明 |
|---|---|
| **口径联动** | 改 `BUILD_Q` 必须同步检查放置目标、产出口径、人口上限三处（见 `09_2` §3.6） |
| **预算约束** | 改 `T(E)` 或 `r_b` 会改变关键路径地块数 → 可能超出地图硬上限（1,350） |
| **规格同步** | 改配置后须回写 `numeric-design.md`，否则重演本轮修正的文档漂移 |
| **回归测试** | `npm test` 含 17 个测试，其中 `r16`（BUILD_Q 预算）、`r15`（奇迹人口乘区）会直接拦截 |
| **多入口一致性** | 涉及加成类配置（如奇迹 `bonus`）须确认**所有读取入口共用同一实现** |

**⚠️ 关键约束（硬锁风险）**：
- E2–E5 的第 3 个里程碑**必须**引用 `G.wonders[era]`（**本时代**奇迹）
- 原因：`startWonderPlacement` 只允许建造 `WONDERS[G.era]`，指向上一时代的奇迹会**永久不可得**
- 而 `starCost = 3` 恰等于里程碑数（**零冗余**）→ 缺 1 星即**时代硬锁死**
- 详见 `08_时代进阶与里程碑.md §3.1`

| 函数 | 签名 | 返回值范围 | 用途 |
|---|---|---|---|
| `hash2(x, y, seed)` | `(number,number,number)=>number` | $[0,1)$ | 确定性哈希（地块变体、噪声基元） |

| `autoRng(G, salt)` | `(G,number)=>()=>number` | $[0,1)$ | 自动建造随机源（⚠️ 依赖 `G.time`，**不可复现**） |

> ⚠️ **`hash2` 精度问题**：乘法中间结果超 $2^{53}$，位混合**有损**。
> 结果是确定性的，但分布质量下降。已登记为低优先级改进项。

### 3.3 地块编码（**双形态，节省体积**）

`state.js encTile(t)`：

```js
function encTile(t){
  const h = r3(t.h);
  // 若全部属性为默认值 → 只存一个数字（高度）
  if(!(t.water|0) && !(t.tree|0) && !(t.zone|0) && !(t.variant|0) && !t.built && !(+t.prog))
    return h;
  // 否则存 7 元组
  return [h, t.water|0, t.tree|0, t.zone|0, r3(t.prog), t.built?1:0, t.variant|0];
}
```

| 形态 | 类型 | 适用 | 体积 |
|---|---|---|---|
| **紧凑** | `number` | 未开发地块（仅高度非默认） | 1 个数字 |
| **完整** | `number[7]` | 有任意非默认属性的地块 | 7 元组 |

**完整形态的字段顺序**（**位置敏感，迁移时必须保持**）：

| 下标 | 字段 | 类型 | 精度 |
|---|---|---|---|
| 0 | `h` | number | r3 |
| 1 | `water` | 0/1 | — |
| 2 | `tree` | 0/1 | — |
| 3 | `zone` | 0–4 | — |
| 4 | `prog` | number | r3 |
| 5 | `built` | 0/1 | — |
| 6 | `variant` | 0–2 | — |

> **实测**：紧凑形态占比约 **12.4%**（规格注释曾写"绝大多数"，已更正）。
