# 18 · 游戏结束条件与终局判定

> 上游：`08_时代进阶与里程碑.md` ｜ 相关：`09_2` §1.4（吸收态）、`05` §4.6（通关）
> 代码基准：`b8f0a66`

## 〇、直接回答

| 问题 | 答案 |
|---|---|
| **胜利条件是什么？** | **建成 E5 的「太空电梯」** —— 唯一条件 |
| **有失败条件吗？** | **【不适用】没有。** 整个代码库中 `G.over` **只在一处被置 `true`**，即通关 |
| **有回合/时间限制吗？** | **没有。** 游戏无限进行 |
| **会"输"吗？** | **不会。** 没有 game over、没有失败画面、没有惩罚性结局 |
| **人口归零会怎样？** | 不结束游戏，但会进入一个**无提示的"空城"状态**（详见 §四） |

> **一句话**：这是一款**只有通关、没有失败**的建造游戏。
> 设计意图上更接近"沙盒 + 阶段目标"，而非"挑战—失败—重试"结构。

## 一、胜利条件（唯一结束条件）

### 1.1 判据

【已实现】`main.js:991 checkFinalWin()`

$$\text{通关} \iff \underbrace{G.era \ge 4}_{E5} \ \wedge \ \underbrace{G.wonders[4]}_{\text{太空电梯已建成}} \tag{55}$$

```js
/** E5 太空电梯完工 → 通关 */
function checkFinalWin(){
  if(G.over) return;                                    // 幂等：已通关则不重复触发
  if(G.era >= 4 && G.wonders[4]){
    G.over = true;
    const win = document.getElementById('winScreen');
    if(win){
      const sub = win.querySelector('.subtitle');
      if(sub) sub.textContent = '文明迈入 · 星际时代';
      const desc = win.querySelector('.desc');
      if(desc) desc.textContent = '太空电梯建成，试炼完成。你的子民已仰望群星。';
      win.classList.remove('hidden');
    }
  }
}
```

**两个条件缺一不可**：
- `G.era >= 4` —— 必须处于 **E5 星际时代**（下标 4）
- `G.wonders[4]` —— **太空电梯**已建成（`WONDERS[4]`）

> 注：`G.era >= 4` 在正常情况下必然成立（否则无法建造 `WONDERS[4]`，
> 因为 `startWonderPlacement` 只允许建造 `WONDERS[G.era]`）。
> 该条件属**防御性冗余**。

### 1.2 太空电梯的代价

【已实现】`config.js WONDERS[4]`

| 项 | 值 |
|---|---|
| 信仰消耗 | $\text{faithCostOf}(4) = \text{FAITH\_ERA\_BASE}[4] \times 100 = 150{,}000 \times 100$ = **15,000,000** |
| 建造时长（文案） | 45 秒 |
| 施工期产能占用 | **9,000 产能/秒**（= E5 刚需工业的全部产能） |
| 信仰库存上限 | 30,000,000（= 花费 × 2） |
| 加成 | **通关** |

**即**：通关需要攒 **1,500 万信仰**，且在施工期间**城市扩张会停滞**
（产能被奇迹独占，建造速度落到下限）。

### 1.3 通关时的表现

| 项 | 内容 |
|---|---|
| 画面 | 显示 `winScreen`（DOM 屏幕，非 3D 场景） |
| 副标题 | 「文明迈入 · 星际时代」 |
| 描述 | 「太空电梯建成，试炼完成。你的子民已仰望群星。」 |
| **游戏是否停止** | **否。** `G.over = true` 仅用于： |

#### `G.over` 的实际作用（4 处）

【已实现】`G.over` 被以下逻辑读取：

| 位置 | 作用 |
|---|---|
| `main.js:504` | tick 门控：`if(G.started && !G.over && !G.paused)` → **通关后经济停止推进** |
| `savepolicy.autosaveTick` | 前置条件 `over` → **通关后不再自动存档** |
| `savepolicy.exitSaveTick` | 同上 → **通关后离场不再保存** |
| `savepolicy.bgSaveTick` | 同上 → **通关后转后台不再保存** |

> ⚠️ **这就是我早先在 `15` 文档里注意到的那处"空 if 体"的真相**：
> `main.js:114 onCloseSaves: ()=>{ ... if(G.started && !G.over) { /* 仍在游戏中 */ } }`
> 该分支**故意留空**，因为关闭存档对话框时无需额外动作。
> 【待确认】属可清理的死分支。

#### 通关后仍可做的事

| 能 | 不能 |
|---|---|
| ✔ 旋转/缩放视角，观看城市 | ✖ 经济不再推进（人口/产出/建造全部冻结） |
| ✔ 打开存档对话框、读取旧档 | ✖ 不能再建造或改造 |
| ✔ 手动存档（`doSave` 不检查 `over`） | ✖ 离场/自动/后台存档均被跳过 |
| ✔ 读取另一个存档槽继续玩别的局 | — |

> **经济冻结已确认为事实**：`main.js:504` 的门控为
> `if(G.started && !G.over && !G.paused){ … tick(gdt) … }` ——
> `G.over` 为真时整个 tick（以及 `tryAutosave`、`updateUI`）都被跳过。
>
> 【待确认】冻结是否**有意**：一种解释是"定格胜利画面"，
> 但副作用是通关后无法以沙盒方式继续观赏/经营。
> 若要做「通关后沙盒模式」，只需解除该门控（或改用独立标志）。

## 二、有没有失败条件？

### 2.1 穷举结论

【已实现】在整个 `js/` 中搜索 `G.over`、`winScreen`、`gameOver`、`lose`、`defeat`、`fail`：

| 搜索结果 | 结论 |
|---|---|
| `G.over = true` 的赋值点 | **仅 1 处** —— `main.js:995`（通关） |
| `winScreen` 的引用 | 仅通关处 |
| 任何"失败/游戏结束/判定失败"的标识符 | **0 处** |

**故：不存在失败条件。** 这是一处**刻意的设计缺失**还是遗漏，资料中未说明——
【待确认】。

### 2.2 玩家实际会遇到的"负反馈"有哪些

> 🔴 **§四「人口 0 空城吸收态」已作废（2026-10-11 复核）**：该状态在游戏中**不可能出现**。
> `main.js` 的 tick 在 `growPop` 之后有 `G.pop = Math.max(1, nextPop)` —— 人口下限是 **1**。
> 我此前的探针绕过了主循环才测出 0。完整证据见
> [`19_核实更正_人口吸收态.md`](19_核实更正_人口吸收态.md)。
> **§四的下文与其"三种修法建议"均不需要**；§四.4 中「无任何缺粮告警」这一条**仍然成立**
> （属独立的体验增强项，不是缺陷修复）。

虽无失败判定，但游戏确实有**惩罚机制**，只是它们不导致结束：

| 负反馈 | 触发 | 后果 | 可恢复 |
|---|---|---|---|
| **缺粮衰减** | 粮产 < 人口消耗 | 人口平滑回落到供养线 | ✔ 划农田即恢复 |
| **人口归零** | 粮产 = 0 且人口已衰减到 0 | 人口冻结在 0（**吸收态**） | ✔ 有农田即可恢复 |
| **建造停滞** | 待建数远超产能 | 建造速度落到下限（71 游戏秒/栋） | ✔ 建工业即恢复 |
| **神力枯竭** | 频繁改造地形 | 无法操作，需等待恢复 | ✔ 恒有 2.5/秒基线 |
| **奇迹施工期停滞** | 在建奇迹 | 城市扩张暂停（产能被独占） | ✔ 刻意的代价设计 |
| **时代无法进阶** | 四项条件未满足 | 停在当前时代 | ✔ 补齐条件即可 |

**关键**：以上**全部可恢复**，故不构成"失败"。

## 三、时代进阶不是结束

【易混淆点】五个时代容易让人误以为"打完 E5 就结束"，但：

| 事件 | 是否结束游戏 |
|---|---|
| 从 E1 进阶到 E2 | ✖ 继续 |
| 从 E4 进阶到 E5 | ✖ 继续 |
| **E5 建成太空电梯** | **✔ 结束（通关）** |
| E5 之后 | **无 E6** —— `progression.eraReadiness` 中 `isLastEra = era >= 4`，判定为"已是最终时代" |

即 **E5 是终点时代**，其唯一目标就是太空电梯。

## 四、⚠️ 一个真实缺陷：「人口 0 空城」状态

> 这是写本文档时**实测发现的**，此前所有文档均未记录。

### 4.1 机制

【已实现】`formulas.js:159 growPop()` 的缺粮衰减分支：

$$\text{若 } \dot F_{out} < \dot F_{need}: \quad N \leftarrow N_{sup} - N_{sup} \cdot \min(0.5,\ \delta) \cdot dt$$

当农田数为 0 时 $N_{sup} = \dot F_{out} / R_{FOOD} = 0$，该式退化为：

$$N \leftarrow 0 - 0 \cdot (\ldots) \cdot dt = 0$$

**衰减分支完全覆盖了 $+0.6\,dt$ 线性增长项** → $N = 0$ 成为**吸收态**。

### 4.2 实测穷举

起始 $N = 0$、住房上限 20（相当于开局的 5 栋房仍在）、模拟 300 秒：

| 农田数 | 粮/s | 供养线 | 300 秒后 $N$ | 结果 |
|---|---|---|---|---|
| **0** | 0 | 0 | **0.000** | ✖ **永不恢复** |
| 1 | 50 | 50 | 20.000 | ✔ 立即恢复 |
| 2 | 100 | 100 | 20.000 | ✔ |
| 5 | 250 | 250 | 20.000 | ✔ |

**分界极其明确**：农田数 $\ge 1$ 即可恢复，$= 0$ 则永久卡住。

### 4.3 为何不构成硬锁

玩家的神力恢复**不依赖人口**：

$$\dot P = 2.5 + \min(10,\ f \cdot 0.02) \ \ge \ 2.5 \ \text{神力/秒}$$

实测（`faithRate` = 0 / 1 / 100）：

| `faithRate` | 神力恢复 |
|---|---|
| 0 | **2.50 /秒** |
| 1 | 2.52 /秒 |
| 100 | 4.50 /秒 |

故人口归零后**神力仍在增长**，玩家总能攒到 **4 点**神力划一块农田自救
（约 1.6 秒即可）。

**所以：技术上不会硬锁，但体验上是缺陷。**

### 4.4 产品层面的问题

| 问题 | 说明 | 证据 |
|---|---|---|
| **无提示** | 人口归零时**没有任何警告** | ✅ 已确认：全 `js/` 内 `缺粮`/`粮食不足`/`饿` 仅出现在**注释**中（`formulas.js:163`、`autobuild.js:85`），**代码层无任何告警** |
| **无解释** | 玩家看到的是"城市空了、人口 0、什么也不发生" | — |
| **易误判为 bug** | 新手可能以为游戏坏了，直接关掉 | — |
| **与"无失败条件"叠加** | 既不会输，也不提示，玩家缺乏"我该做什么"的信号 | — |

### 4.5 三种修法建议

| 方案 | 做法 | 代价 | 副作用 |
|---|---|---|---|
| **A. 加下限** | `growPop` 返回 `Math.max(1, next)`（或 `Math.max(0.5, ...)`） | 极小（1 行） | 人口永不为 0，与"人口是绝对量"的语义一致 |
| **B. 保留吸收态但加提示** | 人口 < 1 时弹 toast / HUD 变红：「子民已离去——划一块农田召回他们」 | 小 | 需 UI 改动；仍保留"饿死"的惩罚感 |
| **C. 让线性项优先** | 缺粮分支改为 `next = Math.max(Math.min(N, N_sup), N_sup - ...)` | 小 | 语义变复杂，需重新验证衰减曲线 |

> **我的建议：B（提示）**，因为"人口会饿死"本身是有意义的惩罚机制，
> 只是不该让玩家**在无提示的情况下**困惑。若想彻底避免，选 A。

## 五、终局状态机

```
                    ┌──────────────────────────────────┐
                    │         未开始 (startScreen)      │
                    └───────────────┬──────────────────┘
                                    │ 注册/登录 → 新游戏或读档
                                    ↓
                    ┌──────────────────────────────────┐
              ┌────→│     进行中 (G.started = true)     │
              │     │     paused 可切换（不结束）        │
              │     └───────────────┬──────────────────┘
              │                     │
   读档/重开  │         ┌───────────┴───────────┐
              │         │                       │
              │         ↓                       ↓
              │   ┌───────────┐         ┌──────────────────┐
              │   │ 人口 0    │         │ E5 + 太空电梯建成 │
              │   │ 空城状态   │         └────────┬─────────┘
              │   │（非结束）  │                  │
              │   └─────┬─────┘                  ↓
              │         │               ┌──────────────────┐
              │         │ 划一块农田     │  通关 (G.over)    │
              └─────────┴──────────────→│  · winScreen 显示 │
                                        │  · 经济冻结       │
                                        │  · 停止自动存档   │
                                        └──────────────────┘
```

**注意**：图中**没有"失败"节点** —— 这是刻意的（或缺失的）设计。

## 六、与「结束条件」相关的设计观察

### 6.1 没有失败条件意味着什么

| 正面 | 负面 |
|---|---|
| 降低挫败感，适合休闲/观赏向 | 缺乏紧张感与决策重量 |
| 玩家可自由实验（划错了拆掉重来） | "缺粮"这个机制的威慑力被削弱（反正不会输） |
| 与"神明"的设定契合（神不会失败） | 没有明确的"我快输了"信号，玩家难以判断自己是否走在正轨 |

### 6.2 唯一的"压力源"是时间成本

由于不会失败，游戏的实际压力来自：

| 压力 | 来源 |
|---|---|
| 人口增长慢 | 指数增长 + 住房/粮食上限 |
| 建造慢 | 产能不足时 71 游戏秒/栋 |
| 信仰积累慢 | 每时代约 100 秒（满规模） |
| 奇迹施工停滞 | 产能被独占 |

即：**惩罚是"变慢"，不是"变坏"**。

### 6.3 资料佐证

【出处】`numeric-design.md` 与 `config.js` 的历史注释中可见：

> **R5：星星仅由里程碑触发（每时代 3 个，一次性）。禁止纯 faithRate 时间出星。**

以及一处测试名称为「R5：里程碑出星 + **五时代不强制 over**」——
说明"不强制结束"是**经过测试确认的有意行为**，而非遗漏。

**结论**：**"无失败条件"是有意设计**；但 §四 的"人口 0 无提示"是**伴生缺陷**。
