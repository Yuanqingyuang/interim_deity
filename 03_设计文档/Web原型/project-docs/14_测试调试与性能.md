## 二、"真门禁"设计（本项目的一条重要工程原则）

### 2.1 问题的由来

【已实现】本项目历史上**多次出现"测试通过但实际有缺陷"**的情况，根因有 4 类：

| 类型 | 实例 |
|---|---|
| **打印型测试** | 只 `console.log` 结果，无断言，永远"通过" |
| **探测语句不会失败** | CI 里 `curl -sf ... && echo "server up"` —— 探测失败不影响 job 结论，导致浏览器回归**长期静默跳过** |
| **恒真断言** | `assert(true, …)`、`n === 0 \|\| n >= 1`、`grp.isGroup !== false` |
| **阈值过宽** | 容差 `TOL = 0.66` 大于被测上界 `BLD_EXTENT = 0.46` → 断言**没有牙齿**，掩盖了真实越界 |

### 2.2 现行原则

| 原则 | 做法 |
|---|---|
| **必须有 `process.exit`** | 任一断言失败即非零退出（浏览器测试亦然） |
| **禁止恒真断言** | 逐条替换为真实断言 |
| **阈值必须有牙齿** | 容差必须**小于**被测量的实际边界 |
| **反向验证（负向测试）** | 见 §2.3 |
| **静态门禁** | 对"难以运行时验证"的约束用源码静态断言（如 `beforeunload` 监听器数量） |

### 2.3 ⭐ 反向验证方法（本项目最重要的实践）

> **每一个修复都必须"注入缺陷 → 确认断言失败"**，
> 否则无法证明断言真的能拦住这个缺陷。

**为什么必须这样做**：本项目有 **4 次**"注释声称已修复、实际是死代码"的记录，其中 **2 次是 AI 自己造成的**。

**典型实例**：

| 修复 | 反向验证方式 | 结果 |
|---|---|---|
| `housingCap` 漏乘 `BUILD_Q` | 注入旧实现（去掉 `× buildQ`）→ 断言应失败 | ✔ 退出码 1，并**指名 E3** |
| `_fitToPlot` 只缩 `scale` 未缩 `position` | 注入旧实现 → 断言应失败 | ✔ 抓到 `fence` 越界 0.608 |
| `wonderPopMult` 丢失 | 注入旧实现 → 断言应失败 | ✔ 抓到"承诺加成但拿不到" |
| `screenToTile` 的 `_terrainVer` | **未做**反向验证 → 补丁被静默回退且无人发现 | ✖ 48 个历史提交中 `_terrainVer` 出现 **0 次** |

**最后一条的教训**：除了反向验证，还必须**回读验证**（改完后读回文件确认内容存在），
因为"写了但没生效"与"没写"在提交信息上无法区分。

### 2.4 静态门禁实例

【已实现】`test/rev-5-save-policy.test.mjs` 末尾：

```js
const mainSrc = fs.readFileSync('js/main.js', 'utf8');
const count = (ev)=> mainSrc.split("addEventListener('" + ev + "'").length - 1;
ok(count('beforeunload') === 1, `beforeunload 注册 1 处`);
ok(count('pagehide') === 1, `pagehide 注册 1 处`);
ok(count('visibilitychange') === 1, `visibilitychange 注册 1 处`);
ok(exitCalls === 2, `beforeunload 与 pagehide 都调用 saveOnExit`);
```

**该门禁的价值已被证明**：在抽 `saveOnExit` 函数时，
`beforeunload` 的**监听器被误删**（注册数由 1 变 0）——
这会直接导致桌面端关页/刷新丢档。静态门禁能立即抓住这类"注册丢失"。

### 3.2 Three.js 垫片机制（重要工程细节）

**问题**：测试需要 `import render.js`，而 `render.js` 里 `import * as THREE from 'three'`。
浏览器靠 `index.html` 的 **importmap** 解析裸模块名，**Node 不支持 importmap**。

**解法**【已实现】`test/support/ensure-three-shim.mjs`：

| 特性 | 说明 |
|---|---|
| **按需生成** | 检测 `node_modules/three` 缺失时才创建 |
| **不改 vendor 原件** | 只做复制 + 重导出，vendored 代码保持只读 |
| **不联网** | 不从 npm 下载 |
| **不污染生产** | `node_modules/` 已在 `.gitignore` |
| **干净检出可跑** | 首次跑测试自动生成 |

> **设计原则（用户明确要求）**：**生产必需的垫片写进代码，测试用的每次按需调用**。
> 本项目无"生产必需垫片"（浏览器有 importmap），故垫片只在测试侧按需生成。

### 3.3 浏览器测试的环境变量

| 变量 | 作用 | 默认 |
|---|---|---|
| `TD_BROWSER_PATH` | 指定浏览器可执行文件 | 自动探测 |
| `TD_BROWSER` | 指定引擎类型 | `chromium` |
| `TD_OUT` | 测试产物（截图/JSON）输出目录 | 临时目录 |
| `GAME_URL` | 被测站点地址 | `http://127.0.0.1:8080/` |

**本项目实测采用系统 Edge**（`TD_BROWSER_PATH` 指向 Edge），
**无需** `npx playwright install` —— 这是为规避"下载浏览器"的网络依赖而做的适配。

### 4.5 扫描性能（autoBuild 路径）

【已实现】`tileIndex` 缓存（2026-10）：

| 项 | 耗时 |
|---|---|
| `tileIndex` 命中缓存 | **0.0001 ms/次** |
| `tileIndex` 未命中（全图扫描，8,100 格） | 0.0682 ms/次 |
| 直接 `eachTile` 全图扫描 | 0.0405 ms/次 |
| **一轮扫描合计** | **0.162 ms → 0.068 ms（−58%）** |

**诚实评估**：一轮 `autoBuild` **端到端约 0.45 ms**，扫描只占其中 0.16 ms，
故本项省下的是单轮约 **0.09 ms**。**对帧时间影响很小**。
真正价值是消除"每轮 4 趟全图扫描"的结构性浪费，并把地块读取收敛到唯一入口。

**等价性验证**：三种子 × 24 轮放置序列**完全一致**（77/77、71/71、85/85）。

### 5.2 失败排查路径

| 症状 | 首查 |
|---|---|
| 时代无法进阶 | `progression.eraReadiness(G).reasons` —— 直接给出缺项中文名 |
| 人口不涨 | `popCap` 口径（是否误传地块数）；当前时代的主导项（E3 起住房无效） |
| 建造极慢 | `buildSpeed` 的 `industries` 是否为逻辑口径；是否在奇迹施工期 |
| 数字与 HUD 不符 | 两处口径是否一致（逻辑 vs 地块） |
| 建筑不显示 | 几何缓存键是否命中（`_geo` 是否被 `new THREE.*` 破坏） |
| 存档失败 | `writeSave` 返回 `null`（配额满）；看 console 的 `[autosave] ... FAILED` |
| 页面卡顿 | `terrainDirty` 节流是否生效；地形重建频率 |
| 拾取错位 | `_terrainVer` 是否随重建递增 |
