# 12 · Unity 最小测试方案

> 交付物（对应 `M15-01`~`M15-05` 的**方案部分**；实际运行需 Unity 环境）。
> 原则（来源：Web 侧最贵的教训，`15` §3.4）：**每个关键断言必须"注入缺陷可失败"**，否则不算门禁。
> ⚠️ **本环境无 Unity/.NET，本文件不包含任何"已运行通过"的 Unity 测试**；Web 侧数据为**实跑结果**（可验证）。

## 一、测试分层

| 层 | 依赖 | 可在无图形 CI 跑 | 覆盖 |
|---|---|---|---|
| **EditMode** | Unity Test Framework（仅编译） | ✅ | 纯公式、进阶条件、地形采样、放置合法性、存档 DTO、配置校验 |
| **PlayMode** | Unity 运行期 + 图形 | ❌（可批处理但更重） | 输入/UI、建筑完成、奇迹触发、暂停/倍速、场景加载与存读恢复、重复读档资源计数 |
| **与 Web 对照** | 固定 seed + 相同输入 | ✅（若为纯逻辑） | 逐函数输出、放置位置、每 tick 资源、进阶可用性、通关 |
| **长时运行** | PlayMode | ❌ | 区块扩张、建筑增多、反复存读、暂停恢复 |
| **性能** | PlayMode + 真 GPU | ❌ | 帧时间、GC Alloc、DrawCall、Mesh 重建、存档耗时与体积 |

## 四、门禁要求（不可让步）

| 要求 | 说明 |
|---|---|
| **真门禁** | 每个测试必须能让流程**失败**（禁止"打印型"测试） |
| **注入验证** | 关键修复必须有"注入缺陷 → 断言失败"的记录（至少：T-E1-04、T-E1-02、T-E1-07、T-P1-03、T-P1-10） |
| **阈值有牙齿** | 容差必须**小于**被测量边界（Web 曾有 `TOL=0.66 > BLD_EXTENT=0.46` 的形式化断言） |
| **禁止恒真** | 不得出现 `Assert.IsTrue(true)`、`n == 0 \|\| n >= 1` 之类 |
| **量纲标注** | 涉及"逻辑数/地块数"的断言必须注明所持口径 |

本清单与 `07` §四的 14 条必测断言一致，**后者是前者的超集**。

## 五、CI 方案

| 项 | 建议 |
|---|---|
| EditMode | CI 跑（无需图形）；使用 Unity 官方 `game-ci` 或自托管 runner |
| PlayMode | 独立 job，允许较慢；失败**不静默跳过** |
| Web 侧 | **保持现状**（`core` 已通过；`browser` 有已登记的独立失败），**不因 Unity 引入而改动** |
| 产物 | 测试报告 + 截图/日志归档 |
| 与 Web 对照 | 固定 seed 集 + 操作序列；**只比分布/结构**（D-11 建议），不追求逐格一致 |

> ⚠️ **不要把 Unity 的失败与 Web 的 `leak-test` 失败混在一起**（用户明确要求独立记录）。Web 侧 `leak-test` 见 `01` §9.3；Unity 侧只做**等价回归**（T-P1-10），不修 Web。
