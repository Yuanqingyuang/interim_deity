## 1. 建模规范

### 1.1 世界比例、占地与高度

| 项 | 规范 | 说明 |
|---|---|---|
| 单位 | Blender 场景单位 = **米**，`Scale = 1.0`，不做非均匀缩放 | 【需在 Blender 验证】导出后 Unity 中 1 格 = 1 单位 |
| 1 格 | = 1.0 × 1.0 世界单位 | 与 `TILE` 一致 |
| **主体占地** | **必须落在 1.0 × 1.0 之内**（俯视投影） | 保证不越格 |
| **受控外挑** | 允许装饰/边界构件外挑，**硬上限：半宽 ≤ 0.65**（即最大外延 0.65 vs 半格 0.5） | 与 Web 现状一致（Web 测试以 0.66 容忍度锁定） |
| **建议目标** | **半宽 ≤ 0.55** | Web 待办指出"24 处外挑若实机观感偏挤可下调"，建议从更保守值起步 |
| 高度分带（住宅，参考） | E1 0.9 ／ E2 1.2 ／ E3 1.4 ／ E4 2.2 ／ E5 1.7 | 沿用 Web 量级；**E4 工业应明显更高**（烟囱/筒仓） |
| 允许的高度范围 | 建筑顶 ≤ 约 3.0（住宅类）；奇迹可更高，但需单独评估遮挡 | 需在 Unity 实机确认不遮挡相邻 |

> **【需在 Blender/Unity 验证】**：上述高度分带是**起点**，不是定稿。首批住宅在 Unity 实机视角下确认"时代可辨识 + 不遮挡"后再冻结。

### 1.2 原点与轴向

| 项 | 规范 | 理由 |
|---|---|---|
| 轴向 | Blender **Z-up / -Y forward**；导出 FBX 时勾选 **Z-up → Y-up（Unity 约定）** | 避免导入后躺倒 |
| **原点位置** | **建筑底面中心**（`(0, 0, 0)` = 占地中心、地面接触点） | 直接对齐格子中心；**不要**用 Blender 默认的几何中心（会导致半埋/半浮） |
| 原点朝向 | 局部 +Z 朝"正面"（正门/入口方向） | 便于朝向旋转 `BLD_ROT` |
| 缩放 | 导出前 `Ctrl+A → Scale`；导出缩放 = 1.0 | 防止导入后比例错误 |
| 旋转 | 导出前 `Ctrl+A → Rotation` | 同上 |

> ⚠️ Web 侧曾发生"建筑部件垂直错位（屋顶升空）"的回归（HEAD commit `9cad171` 即修复此问题）→ **原点/底面基准必须在 Blender 侧一次性定对**。

### 1.3 分体策略（哪些合并、哪些独立）

| 情形 | 策略 |
|---|---|
| 同一建筑的**静态部件**（墙/顶/窗框） | **合并为 1 个 Mesh**（除非需要独立动画/换色） |
| **需要按 `prog` 缩放的**（建造中动画） | 由 Unity 对整体缩放，**不需要**在 Blender 拆分 |
| **需要发光/自发光**的部件（E3/E5 的窗与环带） | **独立对象 + 独立材质**，便于给发光材质 |
| **需要独立朝向或独立替换**的（旗帜、烟囱、水轮） | 独立对象，便于复用 |
| `BUILD_Q > 1` 的**副楼** | 副楼**复用主楼 Mesh**（Unity 侧实例化 / 或用同一 Prefab 缩放副本），**不单独建模** |
| 农田 | 可直接在地表绘制（Web 侧农田 `noBuilding = true`）；Unity 侧可用 1 个低面数模块 Tile 拼装 |

### 1.4 命名、集合与文件命名

```
Blender 源文件：  BS_<Zone>_<Era>.blend           例：BS_House_Feudal.blend
集合（Collection）：按道具拆分                     例：COL_HouseA / COL_HouseB / COL_Shared
对象：            SM_<Zone>_<Era>_<Variant>_<Part>  例：SM_House_Feudal_A_Wall
材质：            M_<语义>_<Era>                    例：M_Wall_Plaster_Feudal
贴图：            T_<语义>_<用途>                   例：T_Building_Atlas_01
导出 FBX：        SM_<Zone>_<Era>_<Variant>.fbx
Unity Prefab：    PF_<Zone>_<Era>_<Variant>.prefab
Unity 材质：       M_<Zone>_<Era>_<Variant>.mat（若必须独有）
```

规则：**全英文、无空格、无中文、`_` 分隔**；同一含义在 Blender / FBX / Unity / 文档中**保持同名**（便于自动校验）。

### 1.5 面数控制

> 任务书明确：**"模型预算应在首批原型测试之后校准，不要在缺乏实测依据时制定过度严格的固定面数指标。"**

因此这里只给**初始参考区间**（**待首批实测校准**），不作为验收门禁：

| 类别 | 初始参考（LOD0 三角面，**待校准**） | 说明 |
|---|---|---|
| 住宅（单栋） | 约 300–1,200 | 俯视视角，仅需看清轮廓与屋顶形式 |
| 农田 Tile | 约 20–100 | 可拼装模块 |
| 工业（含烟囱/筒仓） | 约 600–2,000 | 时代招牌剪影 |
| 教堂 | 约 800–2,500 | 尖顶/柱廊是识别重点 |
| 时代奇迹 | 约 1,500–5,000 | 单座、可更精细 |

**控制原则**：
- 面向**俯视/斜俯视**：**不建模看不见的底面与内部结构**；
- 用**剪影**而非细节区分时代（轮廓、屋顶形式、体量比例）；
- 圆柱/锥体用最少边数（8–12 边）即可；低多边形风格允许明显棱面。

### 1.6 UV、材质数量与纹理

| 项 | 规范 |
|---|---|
| UV | 必须展开；**允许盒式/智能展开**；低多边形风格可用**平铺色块**（极简 UV） |
| 材质数量 | **每个建筑 Prefab 建议 1 个材质**（最多 2：主材质 + 发光材质） |
| 纹理 | **优先共用图集**（`T_Building_Atlas_*`），尺寸 **512 或 1024**；**避免每栋独有贴图** |
| 颜色 | 沿用 Web 时代调色板语义（`PALETTES` / `BUILDING_STYLE`）作为参考；**用户已明确配色先保留、待评估** |
| 色彩空间 | 贴图类型正确（BaseColor = sRGB；几何/遮罩 = Linear） |
| 透明 | **尽量避免**透明材质（性能与排序成本）；必须时限制在极小面积（如玻璃窗） |

**替代方案（推荐评估）**：低多边形风格可直接用**顶点色 + 少量共享材质**——这正是 Web 的做法（`cornerColor` 顶点色 + 程序材质），能显著减少材质球数量并利于 Instancing。**是否采用顶点色方案属【待决策】**（见 `07` 文档 D-14）。

## 2. 资源规范

| 项 | 规范 |
|---|---|
| **Blender 源文件保留** | `.blend` **必须入库**（放 `06_BlenderSource/Buildings/`），以便后续迭代；不得只保留导出件 |
| 导出格式 | **FBX（首选）**；导出设置需固定并记录（Z-up→Y-up、Scale=1、Apply Transform、不导出摄像机/灯光） |
| 备选格式 | glTF/GLB 可作为备选，但**必须实测验证**轴向/材质/贴图关联后再作为标准 |
| 材质与贴图 | 贴图随源文件放 `06_BlenderSource/Materials/`；导出时确保贴图**内嵌或路径可解析**；Unity 侧统一用共享材质 |
| Unity 导入 | 导入后设置：Mesh Compressions 策略、Read/Write 关闭（除非需要运行时读顶点）、材质映射到共享材质、Scale Factor = 1 |
| **Prefab 创建流程** | ① 导入 FBX → ② 检查轴向/比例/原点/材质 → ③ 在 `Prefabs/Buildings/<Era>/<Zone>/` 下建 Prefab → ④ 挂 `BuildingVisual` 组件（仅表现，不含逻辑）→ ⑤ 注册到 `BuildingPrefabProvider` 映射 |

| 版本与命名 | 模型命名见 §1.4；重大改版升 `_v2` 后缀并保留旧版一版周期；记录在 `06_BlenderSource/Documentation/CHANGELOG` |
| 大文件 | 建议 **Git LFS** 管理 `.blend` / `.fbx` / 贴图（见 `09` 文档；D-13【待决策】） |

## 3. 性能规范

| 项 | 规范 |
|---|---|
| **视角优先** | 按**俯视/等距**视角设计：**不为看不见的面增加细节**（底面可省略、内部不建模） |
| 材质球数量 | 单建筑 ≤2；全局共享材质尽量少（利于批处理）；**禁止每栋一个独有材质** |
| 网格数量 | 单建筑合并为尽量少的 Mesh；副楼复用主楼 Mesh |
| 透明材质 | 严控；透明会破坏 Instancing 合批并引入排序开销 |
| **Instancing / 合批** | 已完工建筑走 GPU Instancing（Web 侧 4172 栋 → 约 230 DrawCall 的经验说明"合批是必须的"）；**建造中建筑**需逐栋缩放 → 无法合批，数量受控 |
| **LOD 需求** | **待首批原型实测后再定**：俯视视角 + 城市远景可能有收益；若相机拉远不多，LOD 收益有限，优先用"减少面数 + Instancing" |
| **碰撞体策略** | **建筑默认不加 Collider**。理由：放置基于**格子数据**（占用态由 `TileData.Zone` 提供），拾取走格子坐标（与 Web `screenToTile` 一致），无需物理碰撞。若确有需求（如点击拾取多边形），用**简化凸包/Box**，**禁止复杂 Mesh Collider** |
| 阴影 | 只对**剪影重要**的部件投影；阴影分辨率随城区半径派生（Web 已有此经验：正交框半径上限 120，`far/near` 必须随之派生） |
| 预算校准 | **首批住宅在 Unity 实机测出"同屏 N 栋的帧时间/DrawCall"后**，再回填正式预算；**不预先写死** |

## 4. 美术验收标准（首批住宅必须全部通过）

> 这 7 项与任务书 §4.5 一致；**每项都必须是可执行的检查**，不是主观描述。

| # | 检查项 | 具体判定方法 |
|---|---|---|
| 1 | **Blender 内结构/比例/材质符合规范** | 俯视投影 ≤1.0×1.0（含允许外挑）；高度落在本时代分带；原点在底面中心；材质数 ≤2；对象命名符合 §1.4 |
| 2 | **导出后轴向/比例/原点/材质无错** | 重新导入一个干净 Unity 工程：不躺倒、Scale=1、落格时底面与地面重合（偏差 = 0）、材质不丢 |
| 3 | **Unity 中能正确导入、生成 Prefab、放到格子** | 通过 `BuildingPrefabProvider` 解析到 Prefab；放置后**恰好占 1 格**、无偏移 |
| 4 | **实际游戏视角下能辨别时代** | 截图对照：5 个时代的同分区建筑并排，**不看名字**能区分（轮廓/屋顶/体量/材质任一维度可辨） |
| 5 | **不遮挡相邻建筑、无异常穿插** | 在 8 邻域满排（最小间距）场景下检查：无穿模；对相邻建筑的遮挡面积不超过约定阈值（阈值由实机截图确定） |
| 6 | **材质/网格数/碰撞体满足性能目标** | 材质 ≤2；网格数符合 §1.3；无 Mesh Collider；同屏实例测试达到当前帧率目标 |
| 7 | **更换住宅模型不破坏数据/流程/存档** | 替换前后用**同一存档**读入，建筑数量/产出/人口一致；建造流程可继续 |

> **不通过不得批量建模其他建筑**（任务书 §4.3）。若第 4 项（时代可辨识）不通过，必须先回到 `06_五时代住宅视觉方向方案.md` 修改视觉语言，而不是继续做更多模型。
