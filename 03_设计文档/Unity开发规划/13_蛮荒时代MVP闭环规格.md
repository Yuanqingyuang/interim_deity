### 1.2 关键派生量（E1）

> ✅ 以下数值均以 `node` 直接导入 `js/formulas.js` + `js/config.js` **实算核对**（非文档转述）。

| 量 | 计算 | 值 |
|---|---|---|
| 容纳 200 人所需住房 | `200 ÷ C_HOUSE(4)` | **50 栋**（= `buildingLow` 住房） |
| 供养 200 人所需农田 | `200 × R_FOOD(1) ÷ C_FARM(50)` | **4 块**（粮食功能刚需） |
| 达到门槛所需工业 | `GATE(1) ÷ K_IND(1.0)` = `15 ÷ 1.0` | **15 栋** |
| 单栋耗时（E1 典型：`industries=30, pending=50`） | `V = 0.0840` | **≈11.9 游戏秒**（与 `numeric-design §4.3` 的 0.0840 一致） |
| 单栋耗时（零待建 `pending=0`） | `V = V0 = 0.07` | ≈14.3 游戏秒 |
| 单栋耗时（**零工业**，`floor = 0.5`） | `V = 0.07 × 0.5 = 0.035` | **≈28.6 游戏秒** |
| 单栋耗时（工业不足，`floor = 0.2`） | `V = 0.07 × 0.2 = 0.014` | **≈71.4 游戏秒** |
| E1 满规模信仰/秒 | `FAITH_ERA_BASE[0]` | **15 /s**（阻尼 `D(1) = 0.375`） |
| 巨石阵信仰消耗（E2 才需） | `15 × 100` | 1,500（**E1 用不到**） |

> ⚠️ **发现一处 Web 文档与代码不一致（Z-1）**：`numeric-design.md` §3⑤ 与 `project-docs/06 §3.2` 把"零工业下限 `0.5×V0 = 0.035`"标注为"≈ **14 秒/栋**"，但 `1 ÷ 0.035 = **28.6 秒**"。代码本身自洽（`buildSpeed` 返回 `V0 × 0.5`），**是文档文字算错**。
> 影响：Unity 移植时若照抄文档会得到 2 倍速差。**本项目"以代码为准"**，故 Unity 用 **28.6 秒**；该差异已登记（见 `07` §五 Z-1）。

### 1.4 开局状态（必须自带村落）

> 来源：`numeric-design.md` §3②「开局初始条件」（`terrain.js seedVillage`）

- 原点附近生成 **5 栋住房 + 1 块农田，均为"已建成"态**。
- 住房上限 = `5 × 4 = 20` = 开局人口 → **粮 50/s**。
- 原点若为水面 → 回退到最近陆地。
- **理由**：E1–E2 人口上限 = 住房数 × 4，零住房则 `popCap = 0` → 人口崩溃。此开局是**玩法必要条件**，不是可选美化。

## 二、E1 闭环流程（玩家视角）

```
新游戏（seed）
   │ 生成 4×4 区块 + 出生村落（5 房 + 1 农田，已建成）
   ▼
[改造地形] 抬升/下沉/平整，把目标区推到可建高度 0.95–5.4
   │ 每次扣神力（6–8），神力由信仰产出驱动恢复
   ▼
[划居住] → 住房缺口 → 子民自动建房 → 人口上限提升
   ▼
[划农田] → 粮产上升（保人口不被缺粮衰减）
   ▼
[划工业] → 产能上升 → 建造更快 + 逼近 GATE(1)=15/s
   ▼
[划信仰/教堂] → 信仰上升 → 神力恢复更快
   │ 自动建造每 20 游戏秒按六步优先级落位（住房置顶）
   ▼
[里程碑达成] 人口≥50 · 农田≥10 · 教堂≥1  → ⭐⭐⭐（3 星）
   ▼
[进阶判定] 人口≥200 ∧ 星≥3 ∧ 产能/秒≥15 ∧（E1 无需奇迹）  → 进入 E2 城邦时代
```

**六步自动建造优先级**（`autobuild.js buildOrder()`，E1 同样适用）：
1. 住房置顶（无住房 或 人口 ≥ 住房上限）→ 2. 农田缺口 → 3. 工业缺口（执行层另有 `pop ≥ 15` 门槛）→ 4. 非紧急住房（粮产都有余时）→ 5. 教堂缺口 → 6. 兜底补房。
