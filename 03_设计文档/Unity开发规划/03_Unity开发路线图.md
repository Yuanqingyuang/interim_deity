# 03 · Unity 开发路线图

> 第一阶段交付物 3/9。任务编号与 `02_Unity开发任务清单.md` 对应。
> 阶段划分是**初始方案**，可按实际依赖调整；每个阶段有**唯一检查点（Gate）**，通过后才允许进入下一阶段。

---

## 0. 总体思路

```
阶段 A ──> 阶段 B ──> 阶段 C ──> 阶段 D ──> 阶段 E ──> 阶段 F ──> 阶段 G
审查/决策   数据/地形    建筑闭环    经济/进阶    五时代资产   UI/剧情/结局  优化/回归/发布
工程初始化               (首个时代)   /存档                    (依赖 E)
    │           │            │            │            │            │
    └─ 冻结基线 ─┴─ 可走动地形 ┴─ 可建一座房 ┴─ 可通关(灰盒)┴─ 有时代外观 ┴─ 有叙事结局 ┴─ 可发布
```

**并行原则**：

- **美术（M14）与程序并行**：阶段 A 完成视觉方向后，建模可与 B/C/D 并行，但**首批住宅通过验收前不批量开工**。
- **数值（M6）与美术无依赖**：可最先启动，且最适合在无 Unity 环境下离线准备。
- **禁止**同时重写输入、地形、经济、UI（`Unity移植/05` §5 的明确建议）。

---

## MVP 最小可玩版本（先定义，避免误导阶段划分）

> **目标**：不必等五个时代全部建筑完成，就能在 Unity 里**第一次真正玩到**。

| 项 | MVP 范围 |
|---|---|
| 世界 | 固定 seed 或少量 seed；开局 4×4 区块 + 按需扩展；**地形可由程序生成（无需美术）** |
| 地形编辑 | 抬升 / 下沉 / 平整 / 引水 / 绿化 **5 个工具全部可用**（这是"神力"的核心体验） |
| 分区 | 居住 / 农田 / 工业 / 信仰 **4 类可划**；自动建造可用；8 邻域规则生效 |
| 经济 | 人口 / 粮 / 产能 / 信仰 四资源 tick 推进；缺粮衰减；建造速度模型 |
| 时代 | **至少 E1 → E2 可进阶**（含 3 里程碑 + 进阶判定） |
| 建筑外观 | **灰盒占位体**（20 组合）；**允许**只做 E1/E2 的时代外观分化 |
| 存档 | 单槽保存 / 读取 / 自动保存（不要求迁移器） |
| UI | 顶栏读数 + 工具栏 + 进阶提示（样式可朴素） |
| 相机/输入 | 旋转/平移/缩放 + 划区/施法 + 暂停 |
| **明确不含** | 剧情、档案馆、评分/结局、奇迹（可作为阶段 C 的可选）、完整五时代外观、性能深度优化 |
| **MVP 验收** | 见 `08_MVP范围与验收标准.md` |

> **MVP 对应阶段 A→B→C（含 D 的一部分）**，预计落在 `02` 清单的 P0 里约 **50–60 人日**区间（估算，非承诺）。

## 阶段 A · 仓库审查、技术决策与 Unity 工程初始化

| 项 | 内容 |
|---|---|
| **阶段目标** | 冻结 Web 基线；裁决全部阻塞性决策；建立可编译、可运行、规范化的 Unity 工程骨架 |
| **任务** | `M1-01` 冻结基线 · `M1-02` 版本/平台决策 · `M1-03` 工程创建 · `M1-04` asmdef/命名空间 · `M1-05` 场景与构建配置 · `M1-06` 规范与静态检查 · `M1-07` 配置校验框架 |
| **依赖** | 需先裁决 `01` §11 的 **C-1（目录名）、C-2（工程位置）、C-8（渲染管线）** 与 Unity 版本 |
| **可运行/可体验成果** | 一个**能打开、能构建、能空跑**的 Unity 工程；`Boot → MainMenu → World` 三个空场景可切换 |
| **验收条件** | ① 工程在目标 Unity 版本打开无报错；② 能出一次 Player 构建并启动到 Boot；③ 故意加一条反向程序集引用会产生**编译错误**；④ `git status` 无 `Library/`、`Temp/`；⑤ 规范文档与 `.gitignore` 就位 |
| **主要风险** | 目录名/工程位置未定 → 开工后返工；Unity 版本与目标平台不匹配；把 `Library/` 误提交 |
| **检查点（Gate A）** | **决策表（`07` 文档）中所有"阻塞项"均有明确结论**，且工程构建通过。未通过不得进入 B |

## 阶段 B · 核心数据结构、地形生成与世界渲染

| 项 | 内容 |
|---|---|
| **阶段目标** | 建立确定性世界模型与可复现地形，并把它**渲染出来、能走动** |
| **任务** | `M2-01`~`M2-06` 全部 · `M8-01` 地形网格 · `M9-01/02/03` 输入/相机/拾取（最小可用） |
| **依赖** | 阶段 A 完成 |
| **可运行/可体验成果** | 用固定 seed 生成一座岛；可旋转/平移/缩放观察；地形高度、水陆、色带正确；**能目视与 Web 版对照** |
| **验收条件** | ① 同 seed 两次生成**逐格相同**；② `UnityEngine.Random` 调用数 = 0；③ 负坐标区块换算正确；④ 可建造格数落在 Web 实测区间或**已记录差异原因**；⑤ 建筑贴地高度与网格高度同源（若此阶段已有占位体，偏差为 0）；⑥ 相机不锁原点 |
| **主要风险** | `hash2` 32 位语义在 C# 重写后分布/数值与 JS 不一致；大世界网格重建卡顿；负坐标 floor 写错 |
| **检查点（Gate B）** | **同种子可复现测试通过** + 目视地图与 Web 版同 seed 结果**结构相似**（不要求逐格一致，除非移植同一 RNG，见 `Unity移植/09` §2） |

## 阶段 C · 建筑系统与首个时代的完整玩法闭环

| 项 | 内容 |
|---|---|
| **阶段目标** | 打通"划区 → 自动建造 → 建成 → 产出"闭环，E1 可完整游玩 |
| **任务** | `M3-01`~`M3-06` · `M4-01`~`M4-04`、`M4-06` · `M5-01/02` 灰盒 · `M6-01/02/03/04/05` · `M7-01/02/03` · `M9-04/05` · `M10-01/02`（朴素 HUD） · **`M11-01/02/04` 简化版（单槽保存/读取）** |
| **依赖** | 阶段 B 完成 |
| **可运行/可体验成果** | **可在 Unity 里完整玩 E1 蛮荒时代**：划居住/农田/工业/信仰 → 子民自动建造 → 人口增长 → 达成 E1 三里程碑 → 进阶到 E2；**且能单槽存/读** |
| **验收条件** | ① 划定但未建成的格**不产出**（负向断言）；② 8 邻域规则与非农田密度 ≤25% 成立；③ 六步优先级与住房置顶不变；④ 注入 S-04 缺陷（`cnt+2`）会使测试失败；⑤ 缺粮衰减与帧率**解耦**；⑥ 暂停时资源与进度不变；⑦ 里程碑可达性护栏测试通过（注入错误引用必失败）；⑧ HUD 数字与内部计算同源；⑨ **单槽存/读往返一致；写入失败有提示且旧档不被破坏；坏档整体拒绝且当前世界不变** |
| **主要风险** | 逻辑状态误用 GameObject 承载（后续存档/测试灾难）；口径混淆（逻辑数 vs 地块数）；自动建造与手动划区规则不一致 |
| **检查点（Gate C / ≈ MVP）** | **能不用编辑器手动干预、从头玩到 E2，且存读往返一致**。这是"Unity 版本第一次真正可玩"的节点，应在此**暂停并向用户汇报** |

> ⚠️ **MVP 跨阶段 C/D 边界**（2026-10-10 一致性修正 X-1）：`08_MVP范围与验收标准.md` 的 A18/A19/A20 要求单槽存/读与坏档保护，故阶段 C 必须包含 **`M11-01/02/04` 的简化版**；完整迁移器（`M11-05`）、三条保存路径统一互斥（`M11-03`）、Web v3 导入（`M11-06`）仍留在阶段 D。

## 阶段 D · 人口、经济、时代进阶与存档

| 项 | 内容 |
|---|---|
| **阶段目标** | 完整五时代数据链在灰盒下可通关；存档可靠 |
| **任务** | `M6-06/07` · `M7-04/05/06` · `M11-01`~`M11-05`、`M11-07` · `M10-06`（存档失败提示） · `M4-04` 完整 · `M5-03`（时代外观切换，灰盒级） |
| **依赖** | 阶段 C 完成 |
| **可运行/可体验成果** | 五时代可依次推进；**可建成 5 座奇迹（灰盒）并通关**；存档/读档/自动保存稳定；坏档不会破坏当前世界 |
| **验收条件** | ① 五项奇迹加成为**单一实现点**，HUD 承诺与实际一致（负向测试）；② 通关判定幂等；③ 原子写入：注入中断后旧档可用；④ 三条保存路径统一互斥（迁移 38 条断言）；⑤ 坏档整体拒绝且当前世界不变；⑥ 迁移器可将旧版本样例升到当前；⑦ 信仰库存恒 ≤ 时代上限；⑧ 全时代可通关，**不存在被错误里程碑锁死** |
| **主要风险** | 存档 DTO 泄漏场景引用；"忙而跳过清零累加器"吞掉自动存档；通关后经济冻结语义未决（C-8） |
| **检查点（Gate D）** | **一局可在灰盒下从 E1 通关到 E5**，且存读档往返一致（通关状态、评分快照、剧情标记、档案解锁均可恢复） |

## 阶段 E · 五个时代的建筑资源与视觉表现

| 项 | 内容 |
|---|---|
| **阶段目标** | 用 Blender 资产替换灰盒，五时代**在同一视角下可辨识** |
| **任务** | `M14-01`（视觉方向，已在阶段 A 前完成）→ `M14-02/03`（首批住宅）→ `M14-04`（Unity 接入）→ `M5-05` · 之后 `M14-05` → `M5-06` · `M8-03/04/05` 环境表现 · `M5-04` 变体 |
| **依赖** | 阶段 A 完成后即可并行启动；接入依赖 `M5-01` |
| **可运行/可体验成果** | 五个时代的住宅有明确外观进化；白天/夜晚/阴影/水面/云完整；城市"换时代换装"可见 |
| **验收条件** | ① 首批住宅通过 `06` 文档 §5 的 **7 项验收**；② 更换住宅模型**不破坏**建筑数据/建造流程/存档兼容（替换前后存档可互读）；③ 时代切换时全城外观切换且**不改数据**；④ 变体由确定性哈希决定；⑤ Prefab 资源检查全绿；⑥ 环境表现在目标平台达标 |
| **主要风险** | 建模规范（原点/轴向/比例）不统一 → 无法落格；模型面数/材质数超标；透明材质过多；把 Web 低多边形几何当最终模型 |
| **检查点（Gate E）** | **每时代住宅通过全部 7 项验收**；且**替换模型前后存档互读通过**。未通过不得批量建模其他建筑 |

| 项 | 内容 |

| **任务** | `M10-03/04/05/07` · `M12-01`~`M12-06` · `M13-01`~`M13-05` |

| **验收条件** | ① 事件驱动，**无剧情轮询**（静态检查）；② 序章可跳过且不丢 `storyFlags`；③ 首次神迹**由玩家操作完成**；④ 档案馆官方/私人分类独立，奇迹完成仅轻提示；⑤ 评分每维在真实样本上有区分度；⑥ 极端值不产生 NaN/除零；⑦ 分数在通关时**冻结**，反复打开不变；⑧ 隐藏线索不作通关门槛 |

| **检查点（Gate F）** | **序章 → 五时代剧情 → 通关结算**全链路可走通；评分不重算且有区分度 |

## 阶段 G · 性能优化、回归测试与正式构建

| 项 | 内容 |
|---|---|
| **阶段目标** | 达到可发布质量 |
| **任务** | `M15-01`~`M15-11` · `M8-06/07` 环境分级 · `M9-06` 触控（如需）· `M5-06` 剩余分类建模 |
| **依赖** | 阶段 E/F 完成 |

| **检查点（Gate G）** | **构建版在目标平台完成一局**，性能基线记录成文，发布/回滚预案就位 |

## 与既有 `Unity移植/` 里程碑（M0–M8）的对应

| 既有里程碑 | 本路线图对应 |
|---|---|
| M0 冻结 Web Demo | 阶段 A（`M1-01`） |
| M1 工程骨架/输入/seed 地形 | 阶段 A + B |
| M2 分区/合法性/选址/建筑状态 | 阶段 C |
| M3 固定 tick/公式/进阶 | 阶段 C + D |
| M4 奇迹/胜利/存档 | 阶段 D |
| M5 建筑批次渲染/村民/昼夜水云阴影 | 阶段 E（+ 阶段 C 的渲染基础） |
| M6 六维评分 | 阶段 F（`M13`） |
| M7 序章/档案 | 阶段 F（`M12`） |

> 本路线图把既有 M5 拆成"渲染基础（C/D）"与"五时代资产（E）"，因为**灰盒先跑通玩法**是降低风险的关键；这也是任务书"首批住宅通过验收前不批量建模"的要求。

## 阶段汇报模板（每次到达检查点使用）

到达任一 Gate 后，按以下格式汇报，等待确认再继续：

1. **本阶段完成了什么**（对照该阶段任务 ID）
2. **新增和修改了哪些文件**（路径级）
3. **如何运行和验证**（命令 / 场景 / 步骤）
4. **哪些测试通过或失败**（含失败根因）
5. **还存在哪些问题**（含未决决策）
6. **下一步准备做什么**
