## 二、"Unity 工程与 Blender 源文件是否该放同一仓库"——评估

### 2.1 四个必须考虑的问题

| 问题 | 评估 | 结论 |
|---|---|---|
| **仓库体积** | Unity 的 `Library/`（数 GB）、`Temp/`、`Logs/`、`obj/`、`Build/` **绝对不能入库**；Blender `.blend` 与 `.fbx` 为二进制，单文件可达数 MB | 入库内容可控（只含源 + 导出的交换格式），**体积风险主要来自 LFS 缺失** |
| **Git LFS** | 本沙箱已核实 `git-lfs 3.4.1` 可用 | ✅ **已裁决：启用 LFS**；但 `.blend` 等**大型源文件是否入 LFS 延后决定**（D-13/Q4） |
| **生成文件** | Unity 生成 `Library/`、`Temp/`、`obj/`、`.csproj`、`Logs/`；Blender 可生成 `.blend1` 备份 | 全部 `.gitignore`；**`*.blend1` 必须忽略** |
| **导出资源重复存储** | 同一建筑的 `.blend`（源）+ `.fbx`（交换）**必然同时存在**（源用于迭代，FBX 用于 Unity）。但 Unity 的导入副本在 `Library/`（不入库），故**git 内只有 2 份**，非 3 份 | **可接受**；重复通过"共享图集 + 复用 Mesh"进一步压低 |

### 2.2 方案对比

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| **A. 单仓 + LFS** | 一次 clone 拿到全部；文档/代码/美术同版本；CI 简单 | LFS 增加 clone 成本；需要 `.gitattributes` 规则 | ✅ **已裁决采用** |
| B. 单仓 + 不入库 `.blend`（只入库 FBX） | 仓库更小 | **丢失源文件**，无法迭代建模 —— 违反 `05` §2"源文件必须保留" | ❌ 否决 |
| C. 拆分为"代码仓 + 美术仓" | 两侧可独立权限与体积 | 版本对齐需手工；跨仓引用易漂移 | 仅在美术团队独立时考虑 |
| D. 独立 Unity 仓 + git 子模块 | 隔离彻底 | 子模块维护成本高；本仓库不是为多仓设计的 | ❌ 不推荐 |

**结论：单仓（方案 A）。LFS 已启用；`06_BlenderSource/` 先单独规划，`.blend` 等大型源文件是否纳入 LFS 待首批建筑通过 Unity 导入与验证后再定。**

> **延后的操作含义**：阶段 A 先为 Unity 工程相关二进制（`.fbx`、贴图、音频）配置 LFS；`*.blend` 规则**暂缓**，等首批住宅在 Unity 中导入/验证通过、确认源文件体积与迭代频率后再决定是否纳入。

### 2.4 `.gitattributes` 增补（LFS）

**阶段 A 立即启用**（Unity 工程侧二进制）：

```gitattributes
*.fbx    filter=lfs diff=lfs merge=lfs -text
*.glb    filter=lfs diff=lfs merge=lfs -text
*.gltf   filter=lfs diff=lfs merge=lfs -text
*.psd    filter=lfs diff=lfs merge=lfs -text
*.png    filter=lfs diff=lfs merge=lfs -text
*.tga    filter=lfs diff=lfs merge=lfs -text
*.exr    filter=lfs diff=lfs merge=lfs -text
*.wav    filter=lfs diff=lfs merge=lfs -text
*.mp3    filter=lfs diff=lfs merge=lfs -text
```

**延后启用**（Blender 源文件 —— 待首批建筑通过 Unity 导入与验证后再定）：

```gitattributes
# 暂缓：等首批住宅在 Unity 验证通过、确认体积与迭代频率后再启用
# *.blend  filter=lfs diff=lfs merge=lfs -text
```

> ⚠️ 现有 `.gitattributes` 已含 `* text=auto eol=lf`（用于解决行尾串扰）。**LFS 规则必须放在其后**（后定义的规则优先），并确保未与 `eol=lf` 冲突（二进制走 `-text`）。
> ⚠️ **本仓库当前确无图片/音频资源**（`15` §2.6 已核实：外部图片与音频均为【不适用】，全部程序生成），故上述 LFS 规则不会影响现有内容。
