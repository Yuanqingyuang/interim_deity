# 08 · MVP 范围与验收标准

> 第一阶段交付物 8/9。目的：**不必等五个时代与全部建筑完成，就能在 Unity 里第一次真正玩到**。
> MVP 对应路线图的**阶段 A → B → C（含 D 的一部分）**，见 `03_Unity开发路线图.md`。

---

## 一、MVP 的一句话定义

> **能用神力改造地形、划出四类区域、看子民自动建造、让文明从 E1 蛮荒发展到 E2 城邦，并能存档读档。**

---

## 二、MVP 范围（必须做 / 明确不做）

### 2.1 必须做（In Scope）

| 模块 | MVP 内容 | 对应任务 |
|---|---|---|
| 工程 | Unity 工程可打开、可构建；asmdef 分层；规范就位 | M1-01~M1-06 |
| 世界 | 世界数据模型；**固定 seed + 可选 seed**；确定性生成；区块按需扩展 | M2-01~M2-06 |
| 地形 | 地形生成（大陆/山脊/河谷/河道）；**区块化 Mesh 渲染**；顶点色五段色带 | M8-01/04 |
| 相机/输入 | 旋转 / 平移 / 缩放；Tile 拾取；暂停 | M9-01/02/03 |
| 地形编辑 | **5 个工具全部可用**：抬升 / 下沉 / 平整 / 引水 / 绿化 | M8-02 |
| 分区 | 居住 / 农田 / 工业 / 信仰 **4 类可划** + 拆除 | M3-01/02 |
| 放置规则 | 通用前置 + 8 邻域空置 + 工业距离；**手动与自动共用同一校验器** | M3-01 |
| 自动建造 | 六步优先级 + 打分场选址 + 进度 → 建成 | M3-03/04/05 |
| 经济 | 人口（三重约束 + 缺粮衰减）/ 粮 / 产能 / 信仰；建造速度模型；固定 tick | M6-01~M6-05 |
| 时代 | **E1 → E2 可进阶**（3 里程碑 + 四项条件 + 可达性护栏） | M7-01/02/03 |
| 建筑外观 | **灰盒占位体**（20 组合可放置）；E1/E2 允许有基本形体差异 | M5-01/02 |
| UI | 顶栏读数（时代/人口/粮/产能/信仰/门槛/星）+ 工具栏 + 进阶条件提示 | M10-01/02/04（朴素版） |
| 存档 | **单槽** 保存 / 读取 / 自动保存；失败有提示 | M11-01/02/03/04（简化版） |
| 测试 | EditMode：公式、进阶、地形可复现、放置合法性 | M15-02/03/04 |

### 2.2 明确不做（Out of Scope，留待后续阶段）

| 不做 | 原因 | 归属阶段 |
|---|---|---|
| 五时代完整建筑美术 | 首批住宅需先通过验收 | E |
| 剧情 / NPC 对话 / 档案馆 | 依赖事件节点与 UI 框架 | F |
| 神位评分 / 文明结局 / 神明结局 | 维度未冻结（D-8/Q6） | F |
| 世界奇迹（5 座） | E1 无需奇迹即可进阶；E2 才需要 | D（可提前） |
| E3–E5 的完整数值链与通关 | MVP 只要 E1→E2 闭环 | D |
| 存档版本迁移器 | 单槽 + 同版本先跑通 | D |
| 昼夜 / 云 / 阴影精细表现 | 非核心体验；可在 C 之后补 | E |
| 性能深度优化 / LOD | 需先有内容再优化 | G |
| 移动端 / 触控 | 平台未定（D-5） | G |
| 账号系统 | 首版不需要 | 待定 |

## 三、MVP 验收标准（可执行、可验证）

> 每条都必须**能被一个具体操作或一个自动化测试验证**。禁止用"已创建文件"作为验收。

### 3.1 功能验收（逐条可演示）

| # | 验收项 | 验证方法 | 通过标准 |
|---|---|---|---|
| A1 | 工程可运行 | 在目标 Unity 版本打开并进入 `World` 场景 | 无编译错误、无红字日志；能出 Player 构建 |
| A2 | 地形可复现 | 用同一 seed 生成两次，比较地块指纹 | **逐格相同**；`UnityEngine.Random` 调用数 = 0 |
| A3 | 岛屿合理 | 生成后观察地图 | 存在陆地与海洋；可建造格数量级与 Web 实测（4,979–5,881）**同量级**，差异需记录原因 |
| A4 | 五个地形工具生效 | 依次使用抬升/下沉/平整/引水/绿化 | 每项都能改变地形或植被；扣神力；神力不足时被拒并提示 |
| A5 | 划区 4 类 | 鼠标/触控划出居住/农田/工业/信仰 | 每类可划；拖动连续；不可划在水面/已占用/高度越界处 |
| A6 | 8 邻域规则生效 | 密排非农田建筑 | 隔格放置；非农田密度 ≤25%（铺满测试） |
| A7 | 工业距离生效 | 在居住区旁划工业 | 自动放置时 `D_res ≥ 6` 才落位 |
| A8 | 自动建造 | 划出居住区后等待 | 子民自动建出房屋/农田/工业/教堂（按六步优先级） |
| A9 | 建成才有产出 | 观察建造中 vs 已建成 | 建造中的格**不贡献**产出（负向验证） |
| A10 | 人口增长与缺粮衰减 | 建房屋观察人口；拆除农田观察 | 人口增长至住房/粮食上限；缺粮时**连续回落**（不硬截断、与帧率无关） |
| A11 | 建造速度模型 | 零工业 vs 有工业 | 零工业单栋 ≈14.3 游戏秒；工业不足时明显变慢 |
| A12 | 固定 tick | 暂停后观察 | **暂停时资源、人口、建造进度完全不变** |
| A13 | E1 里程碑 | 达成人口≥50 / 农田≥10 / 教堂≥1 | 三个里程碑各记 1 星，**只记一次**（防重复） |
| A14 | 里程碑可达性护栏 | 注入"里程碑指向上一时代奇迹" | 测试**失败**（证明护栏有效） |
| A15 | E1→E2 进阶 | 满足四项条件后进阶 | 进阶成功；`era` 变为 E2；HUD 与参数同步切换 |
| A16 | 缺条件不能进阶 | 缺任一项时尝试进阶 | 被拒，并提示**缺哪一项** |
| A17 | 灰盒外观可区分 | 观察 20 个组合 | 4 类分区可辨认；E1/E2 有基本形体差异（灰盒级即可） |
| A18 | 存档往返 | 保存 → 重启 → 读取 | 世界/资源/人口/时代/里程碑**全部一致** |
| A19 | 存档失败可见 | 模拟写入失败 | 有**明确提示**；旧档不被破坏 |
| A20 | 坏档保护 | 读取损坏存档 | 整体拒绝；**当前世界不发生变化** |

### 3.2 质量验收（结构性）

| # | 验收项 | 验证方法 | 通过标准 |
|---|---|---|---|
| B1 | 逻辑与表现分离 | 代码检查 | `Simulation`/`World` 程序集**不引用 `UnityEngine` 场景类型**；反向引用会**编译失败** |
| B2 | 无场景当状态 | 代码检查 + 存档检查 | 存档 DTO 中**无** GameObject/Mesh/instanceID 引用 |
| B3 | 无口径混淆 | 测试检查 | 逻辑数/地块数 各有专门断言；传错口径会被测试抓到 |
| B4 | 无恒真断言 | 测试检查 | 无 `Assert.IsTrue(true)` 类断言；关键断言有"注入缺陷可失败"记录 |
| B5 | 无每帧全图扫描 | 计数/性能检查 | 一轮自动建造的地块遍历次数受控（有缓存/索引） |
| B6 | 数值与 Web 一致 | EditMode 对照 | 相同输入的公式输出与 Web 一致（差异需有记录与理由） |
| B7 | 无死字段 | 数据模型检查 | 不携带 `live`、`starProg` 等 Web 死字段 |

### 3.3 MVP 的"完成"定义（Definition of Done）

MVP 视为完成，需**同时**满足：

1. §3.1 的 **A1–A20 全部通过**；
2. §3.2 的 **B1–B7 全部通过**；
3. 存在一份**可复现的操作脚本**（从新游戏到 E2 的步骤 + seed）；
4. 有一份**性能基线记录**（即便粗糙）：同屏建筑数、帧时间、DrawCall、GC Alloc；
5. 有意留在 MVP 之外的内容**已明确列出**（不得含糊）。

## 四、MVP 的风险与前置

| 项 | 说明 |
|---|---|
| **前置** | `07` 文档的阻塞项 **Q1–Q4（Unity 版本 / 管线 / 目录 / LFS）** 必须先裁决 |
| 主要风险 | ① 数值移植后与 Web 不一致；② 地形可复现性在 C# 重写后失效；③ 逻辑状态误用 GameObject；④ 灰盒阶段就把 UI 做得过重（应先朴素） |
| 缓解 | 先在**无 Unity 环境**下把纯逻辑（数值/进阶/放置规则）写成 C# 并配测试；环境就绪后直接接线 |
| 估算 | 落在 `02` 清单的 P0 内，约 **50–60 人日**（单人净工时估算，非承诺；详见 `02` §0 假设） |

## 五、MVP 之后的推荐顺序

```
MVP（A→C，≈ E1→E2 闭环）
   ↓ 汇报并确认
D：完整五时代 + 奇迹 + 通关 + 存档迁移
   ↓
E：五时代建筑资产（首批住宅 7 项验收 → 批量）
   ↓
F：UI 完整 + 剧情/档案馆 + 评分/结局
   ↓
G：性能优化 + 回归 + 正式构建
```
