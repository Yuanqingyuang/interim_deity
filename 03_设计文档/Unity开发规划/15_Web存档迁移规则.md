# 15 · Web v3 存档迁移规则（仅文明进度）

> 交付物（对应 `M11-06` 的**规则定义部分**；导入器实现需 Unity 环境）。
> 依据用户裁决（2026-10-10）：**只迁移文明进度，不迁移原始地形与建筑格子布局**；保留原始 seed 与存档文件；
> 因 Web 存档**缺少地形生成器版本**，必须明确提示"Unity 重新生成的地形不保证与 Web 一致"。
> ⚠️ 本文件**不改变** Web 存档格式，Web Demo 继续独立运行。

## 三、关键转换规则（必须先定义，再实现导入器）

### ① 人口：导入后不得高于新地形的 `popCap`

**问题**：Web 存档的人口是在**Web 地形**上长出来的；Unity 用同 seed 重新生成，地形**不保证一致**，`popCap` 可能更低。

**规则**：
```
pop_imported = clamp( pop_web , 0 , popCap_unity(era, 已建建筑口径) )
```
- **不允许**导入后立刻触发"人口高于上限"的异常状态。
- 若 `pop_web > popCap_unity` → 截断并在导入结果中**报告被截断**（见 §五）。
- **【待确认】**：截断阈值是否改为"按新地形重算的供养线"（粮食约束）而非 `popCap`（住房约束）。建议用 `popCap`（与 Web 一致的主导约束口径）。

### ② 已建成奇迹：只迁移"是否建成"，不迁移"在哪"

**问题**：奇迹在 Web 里是场景中的实体（有坐标），Unity 重新生成地形后原坐标可能不可建。

**规则**：
- `wonders[E] == true` → Unity 记为**已建成**，并**立即生效其加成**（人口乘区 / 信仰乘区，**单一实现点**）。
- **位置**：由 Unity 在生成后的世界里**重新选点**放置（或标记为"无实体已建成"，取决于最终实现）。
- **加成一致性**：导入后必须满足 `wonderPopMult(wonders)` 与 `faithMult(wonders)` 的计算结果，不允许"文案说已建成但加成拿不到"（Web 侧曾发生此回归）。
- **【待确认】**：已建成奇迹在 Unity 世界中是否必须有可见实体（见 §六-2）。

### ③ 里程碑与星：必须校验"可达性"，防止导入出硬锁

**问题**：`starCost = 3` 且每时代恰好 3 个里程碑（**零冗余**）。Web 曾经因"里程碑指向上一时代奇迹"造成**时代链永久锁死**。

**规则**：
```
for E in 0..4:
    for each milestone M in MILESTONES[E]:
        若 M 引用奇迹 W：断言 W == 本时代可建奇迹
    stars(E) = count(starMilestones[E] == true)
    断言 stars_total == Σ stars(E)          // 不得与位图冲突
```
- 导入时若发现位图与 `stars` 不一致 → **整体拒绝**（不做"取其一"的容错）。
- 导入后必须通过**里程碑可达性校验**（`07` §四 第 1、2 条），否则视为导入失败。

### ④ 时代与奇迹的一致性

**规则**：
```
若 era >= 1 且 wonders[E] 缺失（E < era 的奇迹未建成）：
    → 不视为错误（Web 允许 E1 无需奇迹进阶），但记录为"进度不完整"
若 over == true：断言 era == 4 且 wonders[4] == true   // 通关条件（公式 55）
```
- `over == true` 但条件不成立 → **整体拒绝**（视为损坏）。

### ⑤ 资源上限截断（统一）

| 资源 | 截断 |
|---|---|
| 信仰 | `faithCapOf(era) = faithCostOf(era) × 2` |
| 神力 | `powerMaxOf(era) = 100 + era×60` |
| 神迹剩余秒 | `MIRACLES[k].dur` |
| 人口 | 见 ① |

## 四、导入流程（失败即整体拒绝）

```
读取 Web 导出 JSON
  → 校验顶层：对象、v == 3、（v1/v2 需先走 Web 自身迁移语义）
  → 校验字段类型与范围（era/pop/faith/stars/wonders 等）
  → 生成 Unity DTO（只含 §2.1 字段）
  → 用 seed 重新生成世界（Unity TerrainGenerator）
  → 应用 §三 的关键规则（人口截断、奇迹加成、里程碑校验）
  → 运行导入后校验（§五）
       ├─ 全部通过 → 提交到当前会话（新建一个 Unity 存档槽）
       └─ 任一失败 → 整体拒绝，当前世界不变，向玩家给出明确原因
```

**禁止**：部分导入（会产出"半损坏世界"，比明确失败更难排查 —— Web `11` §3.4 已有此教训）。

## 六、待确认（影响实现）

| # | 问题 | 建议 |
