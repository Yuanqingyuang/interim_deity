## 7. 可以直接迁移的算法与数据

> 判定标准：**纯函数 / 纯数据，与 DOM、Three.js、localStorage 无耦合**，可逐行对照重写为 C# 并用同一批测试用例验证。

| 项 | 位置 | 迁移方式 | 风险 |
|---|---|---|---|
| 全部数值公式 | `js/formulas.js`（21 导出） | 逐函数 1:1 重写为纯 C# 静态函数 | 低（有 17 单测作对照基线） |
| 全部配置常量 | `js/config.js` | 转为 `ScriptableObject` 资产 | 低；需保留 `APP_VERSION`/数值版本号 |

**⚠️ 唯一失败根因（已定位到断言，非猜测）：**

```
FAIL  [泄漏] 纹理无泄漏（texLeak=1 ≤ 0）
FAIL  [泄漏] 着色器程序无泄漏（progLeak=3 ≤ 0）
泄漏测试 FAIL：2 项门禁未通过
```

即：**连续 6 次读档后，WebGL 纹理净增 1、着色器程序净增 3**（`leak-test.mjs` 的门禁阈值为 `≤0`）。其余泄漏门禁（缓冲 ≤16、堆 ≤8MB、无 console.error）**均通过**。

> **明确纠正**：该失败**不是** Node.js 版本弃用警告导致的。CI 使用 Node 20（`ci.yml`），日志中的 `npx playwright install` 警告是**提示性信息**，与 job 结论无关；job 失败由 `leak-test.mjs` 的 `process.exit(1)` 触发。
>
> **对 Unity 的影响**：这是 **Web 端** 的纹理/着色器释放缺陷（读档路径 `doLoad → buildTerrain + buildWater + syncWorld` 未完全释放 GPU 资源）。Unity 版有自己的资源生命周期，**不继承**此缺陷；但**应在 Unity 侧建立等价的"重复读档资源计数"回归**（详见任务 T15.x）。

## 13. 结论与建议的下一步

**结论**：

1. **Web 原型是可运行、有测试、有权威数值规格的可靠基线**（14 模块 / 7281 行 / 17 单测全绿 / 数值与代码一致）。
