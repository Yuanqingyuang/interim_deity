## 2. Web 模块到 Unity 的职责映射

| Web Demo | Unity 建议模块 | 迁移重点 |
|---|---|---|
| `js/main.js` | `GameBootstrap`、`GameLoop`、`GameSession` | 拆分主循环、菜单状态、暂停、自动建造、存档接线；避免一个 MonoBehaviour 包办全部逻辑 |
| `js/config.js` | `EraDefinition`、`BuildingDefinition`、`WonderDefinition` ScriptableObject | 配置数据与代码分离，保留数值版本号 |
| `js/formulas.js` | `EconomySimulator`、`PopulationSystem`、`ProgressionRules` 纯 C# 类 | 公式可单测；不要依赖场景对象 |
| `js/state.js` | `WorldState`、`ChunkData`、`TileData`、`Save DTO` | 用字典/数组保存逻辑状态；不要把 GameObject 当存档数据 |
| `js/terrain.js` | `TerrainGenerator`、`TerrainEditor`、`ZonePlanner`、`PlacementValidator` | seed 生成、地形编辑、区域涂画、合法性检查、自动选址分开 |
| `js/render.js` | `WorldRenderer`、`ChunkRenderer`、`BuildingRenderer`、`CitizenRenderer`、`EnvironmentRenderer` | 逻辑与渲染分离；优先 GPU instancing / 合批，按区块更新 |
| `js/ui.js` + HTML/CSS | Unity UI Toolkit 或 uGUI | HUD、分类工具栏、进阶提示、暂停菜单与世界输入协调 |
| `js/auth.js` | `ProfileService`（可选） | 当前本地账号是 Web 端方案；Unity 首版不必照搬密码系统 |
| `js/saves.js` | `SaveService`、版本化 DTO、原子写入 | JSON/二进制均可；临时文件写完后替换正式文件，失败不覆盖有效存档 |
| `js/log.js` | `EventLogService` | 游戏事件日志与叙事档案分开存储 |
| `js/audio.js` | `AudioService` | 统一事件接口，资源后续可替换为正式音效 |
| 无：未来剧情系统 | `NarrativeDirector`、`DialoguePanel`、`ArchiveService` | 由游戏事件触发，不在 Update 中轮询全部剧情条件 |

## 3. 依赖方向

推荐依赖关系：

`Core → Simulation/World/Progression → Events → UI/Rendering/Audio/Narrative`

- Simulation 不依赖 UnityEngine 的场景对象。
- Rendering 订阅世界状态变化，只负责把状态表现出来。
- UI 发送玩家命令，不直接修改内部数据结构。
- Narrative 订阅明确的游戏事件（祈愿出现、神迹成功、时代进入、奇迹完成、通关）。
- SaveService 将逻辑状态序列化；场景重建从数据生成，不反向把场景层级当作真实状态。

## 4. 核心运行模式

- `GameClock` 管理模拟 tick、暂停与倍速。
- `GameCommand` 表达玩家操作，例如 `PaintZoneCommand`、`CastRainCommand`、`RaiseTerrainCommand`。
- `GameEvent` 表达模拟结果，例如 `BuildingCompletedEvent`、`EraAdvancedEvent`、`WonderCompletedEvent`。
- 每个 tick 顺序固定：更新建造进度 → 计算产出/消耗 → 更新人口与资源 → 检查时代条件 → 发布事件。
- 视觉帧率可以变化，但模拟 tick 的规则不能随帧率变化。
