# 数值经济与时代进阶规格

## 1. 数值来源

权威基线是 Web Demo 的 `numeric-design.md` 与 `js/config.js`。迁移时应把现有参数逐项导出并写成 Unity EditMode 测试，不要从本文重新抄一份近似值代替源参数。

## 2. 五时代基线

| 索引 | 时代 | 目标人口 | 时代倍率 | 主导人口约束 | 奇迹 |
|---|---|---:|---:|---|---|
| E1 | 蛮荒 | 200 | 1 | 住房 | 巨石阵 |
| E2 | 城邦 | 2,000 | 10 | 住房 | 金字塔 |
| E3 | 封建 | 8,000 | 40 | 粮食 | 大教堂 |
| E4 | 工业 | 20,000 | 100 | 粮食 | 摩天塔 |
| E5 | 星际 | 60,000 | 300 | 产能 | 太空电梯 |

四类核心建筑：住宅、农田、工业区、教堂。核心资源包含人口、粮食、产能、信仰。

## 3. 规则必须原样核对

公开数值规范明确：
- 人口是绝对人口，时代缩放只通过 `T(E)` 出现一次，避免重复乘时代倍率。
- 粮食、产能、信仰和住房按已建成建筑计产出/容量；区域划定不等于建筑完工。
- 奇迹消耗的是信仰，`faithCost` 由时代参数推导。
- 每个时代有三个里程碑星星；进阶要求人口达标、本时代奇迹、星星达到门槛，并且产能/秒达到 `GATE(E)`。
- 里程碑必须指向本时代奇迹。由于星星门槛没有冗余，引用错误会导致时代永久锁死。
- 信仰有上限，防止跨时代无限囤积后让奇迹瞬间完成。
- 工业批次和选址规则经过多轮调整；不要将文档中已经废弃的布局参数带入 Unity。

具体公式与全部参数以仓库 `numeric-design.md` 为准。本文不重复所有公式，避免产生第二份可能过时的数值真相源。

## 4. Unity 实现约束

- 将公式写成纯 C# 静态/无状态函数，并提供单元测试。
- 所有除法检查分母为零、NaN 和 Infinity；对 clamp、round、取整策略保持与 JavaScript 现有行为一致。
- 固定 tick 的时间单位必须统一。明确暂停、倍速和离线时间是否推进模拟。
- UI 展示值和内部计算值分离；不要通过 UI 的四舍五入结果反算游戏状态。
- `EraDefinition` 中配置人口门槛、奇迹、星星门槛、产能门槛和时代配色，运行时验证配置完整。
- 时代进阶的唯一入口应是 `ProgressionRules.TryAdvanceEra`，HUD 只读取结果，不自行重复判定。

## 5. 移植回归用例

1. 相同输入状态，公式输出与 Web Demo 一致。
2. 已划定但未建成的格不提前贡献产出。
3. 每个时代的奇迹里程碑都引用当前时代奇迹。
4. 缺一颗星时不能误进阶；达到所有条件时可以进阶。
5. 信仰库存始终不超过时代上限。
6. 暂停时模拟时间、资源和建造进度不变化。
7. 速度倍率只按约定影响模拟时间，不意外改变真实时间指标。
