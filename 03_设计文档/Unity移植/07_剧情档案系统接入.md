# 剧情与档案系统接入规格

## 1. 已确定的叙事约束

- 开局有神界画面、神位交接动画与一位前辈神明的快速任务介绍。
- 进入岛屿后，村民最初不知道神明存在。
- 玩家通过首次回应村民祈愿、实现请求，开启神明与文明的关系；游戏玩法由“拯救村民”开始。
- NPC 对神明使用敬语与请求语气，不用命令式台词。
- 玩家不被写成一个独立出场、有固定性格的角色；台词应让玩家感觉自己就是神明。
- 档案馆同时有官方史籍/地方志式记录，以及普通居民日记、书信和手记。
- 剧情是经营玩法的背景与调味品；阅读应当可选，不频繁强制中断操作。
- 文明结局与神位评分是两个维度：前者描述文明面貌，后者依据评分评定。

## 2. 事件驱动，不要剧情轮询

建议剧情事件：
- `IntroStarted`
- `DivineAssignmentPresented`
- `PrayerHeard`
- `FirstMiracleCompleted`
- `ArchiveEntryUnlocked`
- `WonderCompleted`
- `EraAdvanced`
- `FinalWonderCompleted`
- `FinalEvaluationCreated`

`NarrativeDirector` 监听这些事件，并根据存档中的 `storyFlags` 决定播放/解锁哪些内容。不要在每帧 Update 中反复检查所有剧情条件。

## 3. 数据驱动档案

建议 ScriptableObject 类型：
- `DialogueSequence`: 对话序列、说话者、文本、触发条件、可跳过性。
- `ArchiveEntry`: 标题、时代、类型（官方/私人）、作者身份、正文、解锁条件、关联事件、排序权重。
- `StoryFlagDefinition`: 唯一 ID、默认值、是否影响结局。
- `NarrativeEventDefinition`: 游戏事件到剧情响应的映射。

正文可用 Markdown/纯文本源文件维护，再由编辑工具导入；不要把长篇剧情硬编码在 MonoBehaviour。

## 4. 档案呈现规则

- 奇迹完成时只显示轻提示，例如“档案已更新”，不强制打开档案馆。
- 官方记录提供年代、事件、工程和后续影响。
- 居民日记提供个人视角、生活细节和情绪；可以不完整，也可以与官方记录关注点不同，但不要为了制造悬疑而随意写成互相矛盾。
- 早期时代若没有成熟文字系统，可以由后世整理成官方纪事；当代私人日记应符合该时代的记录媒介。
- 隐藏线索是可选阅读内容，未阅读不会阻断时代进阶。

## 5. 首次神迹流程

1. 神界交接短片（可跳过）。
2. 前辈神明用简短对话说明身份、辖区、五时代目标和最终考核。
3. 镜头过渡到村庄，农人因旱情祈愿。
4. UI 高亮甘霖工具，玩家亲自操作。
5. 雨效完成后农人惊讶并以敬语致谢。
6. 解除教学限制，进入正常建造。
7. 解锁第一份记录；不强制玩家立刻阅读。

首次神迹是否免费属于设计决策：若免费，应只对序章教学触发，不改变后续常规神迹消耗规则。
