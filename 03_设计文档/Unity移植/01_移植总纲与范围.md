# Unity 移植总纲与范围

## 1. 目标

将现有《实习神明》Web Demo 的核心玩法迁移到 Unity，同时保留 Web 版作为可对照的原型。移植的目标是**复现玩法规则与玩家体验**，不是逐行翻译 JavaScript，也不是把 HTML HUD 原样嵌进 Unity。

## 2. 现有 Demo 的事实基线

根据仓库公开 README、`docs/project-summary.md` 与 `numeric-design.md`：

- 游戏定位：轻量沙盒 + 放置建造。
- 世界：seed 驱动的程序地形；10×10 tile 区块，开局 4×4 区块；有建筑的区块会补齐 8 邻域区块。
- 地形：域扭曲、大陆度、脊状山脉、丘陵、河谷；包含抬升、下沉、平整、引水、绿化等工具。
- 分区：居住、农田、工业、教堂四类；分区后由系统自动建造。
- 时代：蛮荒、城邦、封建、工业、星际五时代。
- 关键资源：人口、粮食、工业产能、信仰；时代进阶还依赖本时代奇迹和星星/里程碑条件。
- 视觉：低多边形 3D、昼夜光照、实时阴影、云层、水面、时代调色板、建筑与村民模型。
- 账号与存档：浏览器本地用户、3 槽 + 快速存档、JSON 导入导出、自动存档。
- 音频：Web Audio 合成放置、奇迹完成、时代进阶音效。
- 当前胜利流程与规划中的评分、剧情档案系统不是同一件事；六维 1000 分评分和剧情序章属于后续规划，移植时应作为独立模块新增，不能误认为 Web Demo 已全部实现。

## 3. 移植原则

1. **规则优先**：数值公式、时代门槛、建造合法性先建立自动化测试，再实现视觉。
2. **模拟与表现分离**：人口、资源、地形、分区、建筑状态不能依赖 GameObject 是否存在。
3. **确定性**：相同 seed、相同操作序列、相同 tick 输入应产生相同模拟结果。
4. **可暂停、可存档**：模拟时钟独立于 `Time.timeScale`，明确暂停、倍速和存档边界。
5. **渐进迁移**：先做一块小地图和核心循环，再扩到无边界区块、建筑外观、昼夜与大地图性能。
6. **数据驱动**：时代、建筑、奇迹、资源公式、对话与档案使用 ScriptableObject 或 JSON/文本数据，不硬编码到 MonoBehaviour。
7. **Web Demo 保持只读基线**：新旧实现对照时保留 Demo 原样，不在 Unity 分支反向改造 Web 源码。

## 4. 推荐里程碑

- M0：冻结 Web Demo，记录 commit、测试结果、关键截图与 seed。
- M1：Unity 工程骨架、输入/相机、seed 地形与 tile 数据。
- M2：分区绘制、合法性检查、自动选址与建筑状态。
- M3：固定 tick、人口/粮食/产能/信仰公式、时代进阶。
- M4：奇迹建造、胜利条件、存档加载。
- M5：建筑批次渲染、村民表现、昼夜/水/云/阴影。
- M6：六维评分与结算；将评分口径与现有真实可测数据对齐。
- M7：神界交接序章、首次祈愿、官方史籍与居民日记。
- M8：性能、平台输入、存档迁移和回归验收。

## 5. 明确不做

- 不在第一阶段重建复杂账号体系；优先使用 Unity 本地存档身份或匿名档案。
- 不把所有 tile 都创建成独立 GameObject。
- 不把剧情对话塞进模拟主循环。
- 不为移植而擅自改变 Web Demo 数值。若发现规则冲突，先记录差异，再由设计决策确认。
