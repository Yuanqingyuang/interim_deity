# 存档与版本迁移规格

## 1. Web 端基线

当前 Web Demo 使用浏览器本地存储，包含 3 个存档槽、快速档、JSON 导入/导出和自动保存。写入失败可能返回失败结果，调用端需要显示明确提示。

Unity 版不必复制浏览器 localStorage，但必须保留玩家对“可保存、可恢复、失败可知”的预期。

## 2. 建议的存档封装

```json
{
  "schemaVersion": 1,
  "gameVersion": "0.1.0",
  "seed": 12345,
  "terrainGeneratorVersion": 1,
  "savedAtUtc": "2026-01-01T00:00:00Z",
  "session": {},
  "world": {},
  "progression": {},
  "economy": {},
  "narrative": {}
}
```

以上是结构示意，不是现有 Demo 的 JSON 格式。实际字段必须按 Unity 运行时数据定义。

## 3. 保存要求

- 写入临时文件，完整写入并验证后再替换正式文件。
- 保存失败时保留上一个有效存档并告知玩家。
- 自动存档和手动存档使用同一套序列化/校验流程。
- 存档时先生成一致的逻辑状态快照，再执行磁盘 I/O。
- 不将 GameObject instance ID、Mesh 引用或场景对象引用写进持久化数据。
- 导入存档先反序列化到临时 DTO、验证 schema 和所有区块，再提交到当前会话。
- 未知版本、缺字段、超大文件、非法数值与重复区块坐标都要有明确错误处理。

## 4. 必须测试的边界

- 中断写入、磁盘空间不足、文件只读。
- JSON 截断、字段类型错误、NaN/Infinity（若格式允许出现）。
- 存档期间继续运行模拟。
- 加载失败后当前世界不发生部分改变。
- 旧版本升级失败时保留原始文件。
- 通关状态、评分快照、已解锁档案与剧情进度可正确恢复。
