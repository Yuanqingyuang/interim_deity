# 移植风险与决策清单

## P0：开始大规模移植前确认

- [ ] 冻结 Web Demo 的 Git commit，并记录 `npm run verify` 结果。
- [ ] 确认 Unity 目标平台、最低配置、是否需要移动端。
- [ ] 将 `numeric-design.md` 与 `js/config.js` 的参数导出为单一对照表。
- [ ] 明确世界 seed、生成器版本与旧存档兼容策略。
- [ ] 明确暂停、倍速、游戏内时间与真实时间的定义。

## P1：核心玩法阶段

- [ ] 手动分区与自动选址是否使用相同合法性规则？
- [ ] 已划定区域与已建成建筑是否分开计产出？
- [ ] 逻辑建筑总量与渲染抽样/实例上限是否分离？
- [ ] 时代里程碑是否严格引用本时代奇迹？
- [ ] 信仰上限和各资源的溢出/负数规则是否与 Web 一致？

## P1：存档与结束流程

- [ ] 存档快照是否一致？
- [ ] 导入失败是否保持当前世界不变？
- [ ] 自动存档失败是否明确提示且保留旧档？
- [ ] 通关评分是否只计算一次并冻结？
- [ ] 结算状态、剧情标记与档案解锁是否都保存？

## P2：内容与表现

- [ ] 五时代建筑与时代配色映射。
- [ ] 昼夜、阴影、水面、云层是否按平台预算分级。
- [ ] NPC 视觉数量与逻辑人口是否解耦。
- [ ] 档案馆官方记录与居民日记是否独立分类。
- [ ] 序章能否跳过，首次神迹能否通过玩家操作完成。

## 决策原则

没有在源代码/测试中确认的内容必须标为“待验证”，不应把推测写成现状。遇到源文档和代码不一致时，先记录差异、定位权威来源，再决定是否改变设计。
