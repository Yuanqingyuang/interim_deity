# 输入、相机与 UI 移植规格

## 1. Web 端已知交互

- 左键/拖动：施加工具；单击一格、拖动连续操作。
- 右键拖动：旋转视角。
- 中键拖动：平移。
- 滚轮：缩放。
- Esc：暂停菜单。
- 支持触控导航，但移动端小视口仍有待进一步适配。

## 2. Unity 输入设计

推荐用 Unity Input System 将输入映射成语义动作，而不是在各个组件中直接读取鼠标状态：
- `PrimaryPointer`：施法、涂画、选择。
- `OrbitCamera`：旋转。
- `PanCamera`：平移。
- `ZoomCamera`：缩放。
- `Pause`：暂停/恢复。
- `CancelTool`：取消当前工具。

UI 正在接收指针事件时，不应把同一次输入继续传给世界工具。拖动跨越 UI 边缘时要明确是继续绘制还是取消，避免误操作。

## 3. 相机

建议将相机控制拆成 pivot/orbit、平移焦点和距离三个变量。限制俯仰角与缩放范围；焦点应随城区/用户选定位置变化，而不是永久锁定世界原点。

大地图的地面拾取应使用 Physics.Raycast 或自定义 tile picking，并缓存同一 tile 的命中结果；相机移动、地形变更或区块重建时使缓存失效。

## 4. UI 结构

- 顶部：时代、人口、粮食、产能、信仰、速度与暂停。
- 工具栏：地形、区域、操作、视角、神迹、奇迹，允许收起低频类别。
- 进阶区域：当前时代条件与每项条件的真实状态。
- 日志：系统事件与叙事档案分别呈现。
- 存档：多槽位、快速保存/加载、导入/导出与错误提示。
- 结算：最终评分、文明总结、神位等级。

## 5. 不应在第一阶段重做的内容

优先保持操作语义与布局信息架构相似。美术、动画和 UI 风格可以在核心规则验证后重做；不要同时重写输入、地形、经济和 UI，导致难以定位差异。
