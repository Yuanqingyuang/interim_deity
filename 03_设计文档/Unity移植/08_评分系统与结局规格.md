# 评分系统与结局规格（待实现/待校准）

## 1. 状态声明

1000 分制、六维评分和四档神位评定来自项目后续设计讨论，不应标记为当前 Web Demo 已完成的功能。移植前需冻结公式版本，并由真实试玩数据校准阈值。

## 2. 当前讨论中的六维方向

- 人口规模
- 城市/领土规模
- 环境美化
- 信仰积累
- 分区均衡
- 进阶效率

此前讨论过两种命名策略：保留旧维度名称并替换不可测子项，或直接重映射为真实可测维度。需要在实现前做一次正式决策，避免 UI 名称与算法含义不一致。

## 3. 已知问题与风险

- “世界奇迹”如果每时代强制建造，则通关时五座齐全，无法区分玩家表现，不适合作为独立评分维度。
- 项目没有真实的星际殖民地、行星改造或太空电梯速度统计时，不应把这些不存在的数据伪装成评分依据。
- 人口对数刻度的满分基准、领土面积基准、信仰满分阈值都需用当前实际数据验证。
- 环境评分要定义统计范围、绿化、水域、地形改造和奇迹计数口径。
- 分区均衡公式必须处理建筑总数为零、分母为零以及极端比例。
- 进阶效率需明确使用真实墙钟时间还是游戏内时间；倍速和暂停不能无意中给出反向激励。
- 结算分数必须在通关时冻结并保存，不能在结算界面打开时重新按变化中的状态计算。

## 4. 推荐实现顺序

1. 写清楚每个维度的输入字段、范围、归一化方法和缺失数据行为。
2. 用真实存档/自动化场景生成样本，检查每个维度是否有区分度。
3. 对极端值和无效值做单元测试。
4. 计算总分并冻结 `ScoreSnapshot`。
5. 根据分数产生神位等级；根据各维度表现生成文明结局摘要。
6. 保存结算快照与剧情档案解锁状态。
